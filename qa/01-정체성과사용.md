# 파트 1. 정체성·목적

### Q1. 다듬이 뭔가요?
🟢 한국어 **맞춤법·띄어쓰기·조사·문법**을 교정해 주는 도구입니다. 틀린 곳에 밑줄이 그어지고 클릭 한 번에 고칩니다.
📎 책 0장, README

### Q2. 한 문장으로 특징을?
🟢 **"틀리게 고치는 것을 가장 무겁게 보는, 완전 로컬 교정기."**
📎 책 13장 원리 1.1

### Q3. 왜 만들었나요?
🟢 기존 교정기는 **멀쩡한 글을 틀리게 고치는 일**이 있어, 한 번 겪은 사용자는 도구를 끈다는 문제의식입니다.
📎 DESIGN.md 1.1: "틀리게 고침 → '얘 뭐야' → 한 번이면 끈다"

### Q4. 어디서 쓸 수 있나요?
🟢 **웹 앱 · 크롬 확장 · macOS 앱** 세 가지입니다. 셋 다 같은 엔진을 씁니다.
📎 책 12장

### Q5. 어떤 오류를 잡나요?
🟢 다섯 종류: **맞춤법 · 띄어쓰기 · 조사 · 문법 · 문체**.
📎 `schemas.py`의 `Category` = spacing / spelling / josa / grammar / style

### Q6. 외부 AI(GPT 등)를 쓰나요?
🟢 **아니요.** 외부 API를 부르지 않고, 모델은 이 저장소에서 처음부터 학습한 작은 모델들입니다.
📎 NOTICE: "no external AI service is called at build or run time"
⚠️ 초기(7월)에는 Gemini 3층이 있었으나 9/15에 **제거**했습니다.

### Q7. 글이 외부로 나가나요?
🟢 **안 나갑니다.** 서버가 내 컴퓨터(`localhost`)에서 돌고, 확장은 `localhost:8000`으로만 보낼 수 있게 묶여 있습니다.
📎 SECURITY.md

### Q8. 회원가입·결제가 있나요?
🟢 **없습니다.** 7월에 만들었던 계정·결제 기능은 9/15에 전부 제거했습니다.
📎 커밋 `feat!: remove billing, accounts, and the service layer`

### Q9. 이름 "다듬"의 뜻은?
🟢 "글을 다듬다". 슬로건은 **"거친 생각에서, 단단한 문장으로."** 모델군 이름 "결(Gyeol)"은 나뭇결을 따라 깎는다는 뜻입니다.
📎 README, `linear_model.py` 설명

### Q10. 누가 만들었나요?
🟢 저장소 소유자(zmflm0110)가 7/14~9/17에 253커밋, 다른 계정(byeolki)이 9/15~9/21에 124커밋을 했습니다.
📎 `git log` 집계
⚠️ zmflm0110 커밋 253개 중 239개에 `Co-Authored-By: Claude`가 붙어 있습니다(Claude Code 세션으로 작성).

### Q11. 라이선스는?
🟢 코드는 **MIT**입니다. 데이터(위키백과 CC BY-SA 4.0, nsmc CC0)는 각자의 라이선스를 따릅니다.
📎 LICENSE, NOTICE

### Q12. 오픈소스인가요?
🟢 코드 라이선스는 MIT(오픈소스 라이선스)입니다. 단, 제가 확인한 시점에 `dadeum-book` 책 저장소는 **비공개**입니다.
📎 `gh repo view`로 확인(책 저장소). 다듬 본 저장소의 공개 여부는 확인하지 않았습니다.

### Q13. 한국어만 되나요?
🟢 네. 한글이 들어간 글만 검사합니다(확장은 한글이 없으면 건너뜀).
📎 `content.js`의 `HAS_KOREAN`

### Q14. Grammarly나 다른 한국어 교정기와 뭐가 다른가요?
🟢 ① 완전 로컬, ② **오탐 최소화를 설계 원칙으로**, ③ 성적(특히 처음 보는 문장)을 정직하게 공개.
⚠️ 다른 제품의 성능과 직접 비교한 데이터는 이 자료에 **없습니다**. 비교 수치를 말하지 마세요.
📎 DESIGN.md 1.x, 책 11장

# 파트 2. 사용법·화면

### Q15. 어떻게 실행하나요?
🟢 서버를 띄우면 됩니다.
```
cd backend && python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --port 8000      # http://localhost:8000
```
📎 README "실행 방법"

### Q16. 맥 앱은 어떻게 설치하나요?
🟢 `sh desktop/make-app.sh` → `/Applications/DaDeum.app` 설치, 첫 실행 때 **손쉬운 사용 권한**을 켭니다.
📎 README

### Q17. 밑줄 색은 무슨 뜻?
🟢 **카테고리**입니다(맞춤법·띄어쓰기·조사·문법·문체). 테마(밝음/어두움)와 상관없이 색이 카테고리를 뜻합니다.
📎 README

### Q18. 실선과 점선의 차이?
🟢 **실선** = 확실(high/medium), 클릭하면 바로 고침. **점선** = 애매(low), 설명만 하고 자동으로 안 고침.
📎 책 5장, `isActionable()`

### Q19. 카드에는 뭐가 나오나요?
🟢 **무엇을 → 무엇으로, 왜**(규정 조항·반례까지). 버튼은 **교정 · 무시 · 이 표현은 항상 허용** 세 갈래.
📎 README "카드는 '고쳐라'가 아니라 '왜'를 말합니다"

### Q20. 한 번에 다 고칠 수 있나요?
🟢 **"모두 고치기"**가 실선만 앞에서부터 차례로 고칩니다. 점선은 건드리지 않습니다.
📎 책 12장 `applyAll`

### Q21. 실수로 고쳤으면?
🟢 **되돌리기(undo)**, 최대 50단계. 모두 고치기는 한 번에 묶여 되돌려집니다.
📎 `MAX_UNDO = 50`

### Q22. 틀리지 않았는데 지적하면?
🟢 **무시**(그 교정만) 또는 **항상 허용**(그 단어를 개인 사전에). 신고하면 그 문장이 회귀 테스트가 됩니다.
📎 책 12장, README "함께 만들기"

### Q23. "항상 허용"은 어디에 저장되나요?
🟢 **브라우저/앱의 로컬 저장소**뿐입니다. 서버로 안 갑니다.
📎 SECURITY.md

### Q24. 키보드 단축키는?
🟢 `Tab` 차례로 고치기, `F3` 하나씩 넘겨보기(웹), `⌃⌥D` 맞춤법 검사 창(맥).
📎 README

### Q25. 얼마나 긴 글까지?
🟢 서버는 **2만 자**, 웹 화면은 현재 **5천 자**까지입니다. 서버는 4천 자씩 문장 경계에서 잘라 돌립니다.
📎 `CheckRequest max_length`, `MAX_TEXT_LEN`, `CHUNK_LIMIT`

### Q26. 타이핑하면 바로 검사하나요?
🟢 네. 단어·문장이 끝나면 0.25초, 멈추면 0.7초, 어떤 경우에도 **최대 0.9초** 안에 한 번 검사합니다.
📎 `AUTO_CHECK_*`

### Q27. 한글 입력 중에 방해되지 않나요?
🟢 **조합 중에는 아무것도 안 건드립니다**(compositionstart~end).
📎 `content.js` 맨 위 "Critical Korean-specific rule"

### Q28. 사파리·모바일은?
🟢 사파리는 **맥 앱이 담당**합니다(다듬 확장이 없으므로 맥 앱이 비켜서지 않음). 모바일은 **미착수**입니다.
📎 `extensionCoveredBrowsers`, PLAN-system-wide-assistant 로드맵

# 파트 3. 전체 구조

### Q29. 전체 구조를 한 그림으로?
🟢
```
화면(웹·확장·맥) ─POST /api/check→ 서버
   서버: ① 형태소 분석 → ② 검사기 21개가 후보 제출 → ③ 겹치는 후보 정리
화면 ←─ issues[] ── 밑줄·카드·고치기 (공유 코어가 상태 관리)
```
📎 책 0·5장

### Q30. 서버와 화면을 왜 나눴나요?
🟢 교정 로직을 **한 곳**에 두고 화면 세 개가 같은 서버를 쓰게 하려고요. 로직이 흩어지면 어긋납니다.
📎 책 4장

### Q31. 엔진은 무슨 언어/틀?
🟢 **Python + FastAPI**. 의존성은 6개(fastapi, uvicorn, gunicorn, kiwipiepy, pydantic, python-dotenv).
📎 README

### Q32. 형태소 분석은 직접 만들었나요?
🟢 **아니요, Kiwi(kiwipiepy)라는 외부 라이브러리**입니다. 규칙 검사기 대부분이 Kiwi 분석 위에서 돕니다.
⚠️ "전부 직접 만들었다"고 말하면 안 됩니다. **직접 학습한 것은 결(Gyeol) 모델군**입니다.
📎 NOTICE에는 Kiwi가 적혀 있지 않습니다(보완 필요).

### Q33. 검사기가 몇 개인가요?
🟢 엔진에 등록된 검사기(`GENERATORS`)가 **21개**, 지적의 출처(source)는 **58개**입니다.
📎 `engine.py`, `sources.py`

### Q34. 검사기들은 어떻게 협력하나요?
🟢 서로 모릅니다. 각자 후보를 내고, **마지막에 한 번 병합**이 정리합니다.
📎 책 5장

### Q35. 겹치면 누가 이기나요?
🟢 ① **고칠 말이 있는 쪽** ② 출처 우선순위(규칙 6 > 사전 5 > 모델 4 > …) ③ 같으면 먼저 나온 쪽.
📎 `merge_and_dedupe`

### Q36. 왜 "제안 있는 쪽"이 먼저인가요?
🟢 이상탐지가 `자률신경` 전체를 잡아 그 안의 `률→율` 교정이 사라지는 사고가 있었기 때문입니다.
📎 DESIGN 1.4

### Q37. "층"은 무슨 뜻?
🟢 분류 이름입니다. **규칙 / 모델 / 조언** 세 종류. 실행 순서가 아니라 구분입니다.
📎 `sources.py` layer

### Q38. 한 층이 고장 나면?
🟢 **그 층만 조용히 빠지고 앱은 뜹니다.** 어느 층이 켜졌는지는 `/api/health`로 봅니다.
📎 DESIGN 1.5·1.6

### Q39. 응답 시간은?
🟢 문서 기준 짧은 문장 약 2ms, 1,400자 약 90ms. **서버를 처음 띄운 직후 첫 요청만** 사전 적재로 수 초.
📎 DEPLOY.md, 제가 직접 측정한 첫 요청 4.3초(콜드 스타트)

### Q40. "공유 코어"가 뭔가요?
🟢 밑줄·고치기·무시·되돌리기 **상태 관리를 한 번만 쓴** 코드(JS 원본 + Swift 포팅, 같은 테스트).
📎 책 12장

### Q41. 왜 공유 코어를 만들었나요?
🟢 같은 로직이 세 화면에 **따로 구현돼 서로 어긋났기** 때문입니다.
📎 README "공유 클라이언트 코어"

### Q42. 코어를 확장도 쓰나요?
🟢 **일부만** 씁니다(signature, isActionable, isIgnored). 교정 적용은 아직 자체 구현입니다.
📎 README 한계 표
