# 파트 5. 모델·데이터

### Q75. 직접 만든 모델이 정확히 뭔가요?
🟢 **결(Gyeol) 모델군**: 혼동쌍 판별 6개(4개 가동), 단어 경계 판별기, 형태소 언어모델(gyeol-lm), 어절 사전. 띄어쓰기 BiGRU 태거는 별도입니다.
📎 책 7–9장, NOTICE

### Q76. "직접 학습"의 범위는?
🟢 데이터 수집 → 문제·정답 생성 → 학습 → 문턱 선택 → 배포 파일 변환이 **전부 이 저장소 코드**입니다. 빌린 것은 학습 알고리즘(scikit-learn)과 코퍼스 원문뿐입니다.
📎 NOTICE

### Q77. 사전학습 모델(BERT 등)을 안 쓴 이유는?
🟢 "확실하게 작동"이 목표였고, 실제로 시험한 외부 교정 모델(KoBART 기반)이 **규칙 시스템보다 성능이 낮고 새 오류를 만들어** 통합하지 않았다는 기록이 있습니다.
📎 CONTEXT.md(과거 기록)
⚠️ 일부 비교 실험 코드(`train_spacing_bert.py`, klue/roberta-base)는 있으나 **배포물에 포함되지 않습니다**.

### Q78. 모델이 정확히 어떻게 판단하나요?
🟢 헷갈리는 자리를 `▒`로 가리고 **앞뒤 12글자**를 봅니다. 글자 2~4조각마다 학습된 가중치를 더해 확률로 바꿉니다(로지스틱 회귀).
📎 책 7.5 (손계산이 모델 출력과 일치)

### Q79. 딥러닝인가요?
🟢 **혼동쌍·경계 모델은 아닙니다**(글자 조각 + 로지스틱 회귀, 선형 모델). 띄어쓰기 태거만 BiGRU 신경망입니다.
📎 `train.py`, `spacing_model_nn.py`

### Q80. 왜 선형 모델인가요?
🟢 작고(모델당 약 5.7MB), 빠르고, **판단 이유(어느 조각이 밀었나)를 손으로 계산해 설명**할 수 있기 때문입니다.
📎 책 7.5

### Q81. 학습 데이터에 오류 문장이 필요한가요?
🟢 **필요 없습니다.** 맞는 글에서 슬롯을 가리면 원문 글자가 곧 정답입니다. 문제와 정답이 같이 생깁니다.
📎 책 7.3

### Q82. 데이터는 어디서 나왔나요?
🟢 **한국어 위키백과**(CC BY-SA 4.0)와 **nsmc 영화평**(CC0).
📎 NOTICE

### Q83. 위키는 격식체인데 구어는요?
🟢 약점입니다. 구어 시드 문장을 손으로 보탰고, 언어모델에는 구어를 8배 가중해 넣었습니다. `데/대`·`러/려`는 구어 표본이 없어 **꺼 놓았습니다**.
📎 `COLLOQUIAL_SEED`, `train_ngram_lm.py`

### Q84. 과적합은 어떻게 막나요?
🟢 시험용을 **문장 단위**로 분리(같은 문장의 슬롯이 양쪽에 안 들어가게), 평가 문장은 학습에서 제외, 평가셋도 세 개로 나눠 처음 보는 문장을 따로 봅니다.
📎 책 7.7, 8.9

### Q85. 확률 문턱은 누가 정하나요?
🟢 **측정이 정합니다.** 정문 오탐률 ≤0.5%를 지키는 가장 낮은 문턱을 자동 선택하고, 못 맞추면 모델을 싣지 않습니다.
📎 `train.py`

### Q86. 문턱이 모델마다 다른가요?
🟢 네. an 0.5 · doe 0.6 · den 0.7 · roseo 0.7 · (꺼 둔) reo/dae 0.8 · 경계 0.97.
📎 `meta.json`, `boundary_meta.json`

### Q87. 모델이 확신해도 틀릴 수 있잖아요?
🟢 그래서 **문법으로 답이 정해지는 자리는 규칙이 먼저** 확정하고(`되`+`고` 등), 모델이 자신 있게 틀리는 부류(이름 속 `든`, 연결어미 `-되`)는 품사로 **잠급니다**.
📎 책 7.9 게이트 표

### Q88. 로서/로써가 약한 이유는?
🟢 수단/자격은 **의미** 차이라 글자 창으로는 잘 안 보입니다. 모델 단독 재현율 20%, 규칙 포함 엔진 재현율 약 85%.
📎 `meta.json`(0.203), pipeline(0.8503)

### Q89. 경계 모델은 뭘 하나요?
🟢 Kiwi가 "여기 띄우자"고 한 자리마다 **진짜 단어 경계인지** 판정합니다. 새 경계를 스스로 찾지는 못합니다.
📎 책 8장

### Q90. 경계 모델 성능이 낮아 보이는데요?
🟢 문턱 0.97에서 진짜 경계의 **9.3%만** 모델 혼자 고칩니다. 대신 정문 문장을 잘못 끊는 비율이 0.03%입니다. **"확실한 것만 잡는" 설계**입니다.
📎 `boundary_meta.json`

### Q91. 데이터를 더 늘리면 좋아지지 않나요?
🟢 5번 재학습으로 확인했는데 **제자리**였습니다. 데이터가 많을수록 오탐 추정이 정확해져 문턱이 올라가고, 얻은 만큼 잃습니다. 한계는 모델 종류에 있다고 기록돼 있습니다.
📎 `train_boundary.py` 설명

### Q92. 언어모델(gyeol-lm)은 뭔가요?
🟢 형태소 3개씩 묶어 센 표로, 두 표기 중 **어느 쪽이 더 한국어다운지 점수**를 냅니다. 고칠 말은 **만들지 않고 순위만** 매깁니다.
📎 책 9.5

### Q93. 언어모델이 후보를 만들지 못하게 한 이유?
🟢 만들면 엔진이 말하는 범위가 넓어져, 새 오탐이 **측정 밖에서** 생기기 때문입니다.
📎 `rescore.py` 설명

### Q94. 어절 사전은 뭔가요?
🟢 위키에서 어절별 등장 횟수를 센 표(**1,806,050개**, 21.7MB). "이 말이 있는가"와 "얼마나 흔한가"를 답합니다.
📎 책 9.1

### Q95. 사전에 단어 대신 해시를 저장하는 이유는?
🟢 메모리 때문입니다. 해시 충돌이 나면 "모르는 말을 안다고 착각"하는 쪽(놓침)으로 틀려서 **안전한 방향**입니다.
📎 `lexicon.py`

### Q96. `.ddm`은 뭔가요?
🟢 다듬이 정한 모델 파일 형식입니다. sklearn 없이 읽혀서 메모리가 117MB → 5.7MB, 변환 때 원본과 확률을 대조(최대 오차 5.55e-16)합니다.
📎 책 7.8

### Q97. 모델 파일 크기는?
🟢 혼동쌍 `.ddm` 각 2~6MB, 경계 5.7MB, 언어모델 36MB, 어절 사전 22MB.
📎 `ls ml/models`

### Q98. BiGRU 태거는 왜 배포에서 빠졌나요?
🟢 torch(딥러닝 라이브러리)가 필요한데 배포 이미지에 설치하지 않기 때문입니다. 지표 기여도(`l1_recall`)는 0.0012로 미미합니다.
📎 README 한계 표

### Q99. 학습을 직접 해 볼 수 있나요?
🟢 `python -m ml.generate_data fetch → build`, `python -m ml.train`, `python -m ml.export_models`.
📎 `ml/` 각 파일 상단 사용법

### Q100. 학습형 교정(문장 통째 고치기)은 시도했나요?
🟢 7/24에 시도했고 **안전선(오탐 하한)을 못 넘어** 접었습니다. 이후 "좁은 판정을 정확히" 방향으로 갔습니다.
📎 커밋 `Per-edit-type gating: decisive negative result redirects the strategy`, docs/PLAN-learned-gec.md
