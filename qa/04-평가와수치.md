# 파트 6. 평가·수치

> 수치는 2026-10-11에 제가 `python -m eval.pipeline`과 `eval.real_errors.score`를 **직접 돌려** 얻은 값입니다. README 값과 다른 곳은 표시했습니다.

### Q101. 정확도가 몇 %인가요?
🟢 질문에 따라 답이 다릅니다. **고친 것 중 맞은 비율(정밀도) 99.2%**, **사람이 쓴 오류를 자동으로 고치는 비율 약 67~74%**.
⚠️ "정확도 99%"만 말하면 과장입니다. 반드시 둘을 같이 말하세요.

### Q102. 정밀도가 뭔가요?
🟢 엔진이 "고쳐라"고 한 것 중 **실제로 맞게 고친** 비율. 측정값 0.9921(하한 0.97).

### Q103. 재현율은요?
🟢 실제 오류 중 **잡아낸** 비율. 합성 오류 기준 규칙층 97.9%, 혼동쌍 99.2%. **실사용 오류 기준은 Q105.**

### Q104. 정문 오탐률은?
🟢 **0.00%**(하한 ≤0.2%). 맞는 글 9,765문장에서 건드린 비율입니다.

### Q105. 실제 사람이 쓴 오류는 얼마나 잡나요?
🟢 자동교정 기준 **dev 74% · holdout 72% · holdout2(처음 본 문장) 67%**, 점선 포함 81/75/72%.
⚠️ README는 holdout2를 63%로 적고 있습니다. 제 측정은 67%이고 차이의 원인은 확인하지 못했습니다. 발표에서는 **"60%대 중후반"**이라 하세요.

### Q106. 왜 세 개로 나눠 쓰나요?
🟢 dev는 규칙을 만들 때 계속 보는 셋(과적합), holdout은 규칙 만들기 전에 봉인했지만 이후 여러 번 봄, holdout2는 **처음 보는 문장**. 차이가 곧 과적합의 크기입니다.
📎 README

### Q107. 합성 오류 점수와 실사용 점수가 왜 다른가요?
🟢 합성 오류는 **규칙이 넣은 오류를 규칙이 잡는** 구조라 순환입니다. 같은 엔진이 합성 93.8%, 실사용 약 15%(당시)였습니다.
📎 `score.py` 설명

### Q108. 평가에 쓴 데이터는?
🟢 정문 9,765(위키) · 합성 오류 3,871 · 규범 예문 225 · 구어 정문 3,000/오류 1,073(nsmc) · 실사용 오류 dev 300/holdout 199/holdout2 150문장.
📎 README "평가 데이터"

### Q109. 실사용 오류는 누가 표시했나요?
🟢 **주석자 한 명(Claude)**, 한글 맞춤법 기준. 경계 사례가 섞여 있어 **절대값보다 변화량**을 봅니다.
⚠️ 주석자가 1명이라는 점이 약점입니다.

### Q110. 어떤 부류를 잘 잡고 못 잡나요?
🟢 (dev) 의존명사 94% · 시간명사 88% · 관형사 86% / **기타 34% · 구어 표기 38%**. 조사는 점선 포함 86%.
📎 `score.py dev` 출력

### Q111. 구어(카톡·댓글)는요?
🟢 재현율 **95.2%**입니다. 구어 **정밀도는 재지 않습니다** — 구어 "정문"에도 실제 띄어쓰기 오류가 많아 코퍼스를 재게 되기 때문입니다.
📎 pipeline `[casual]`

### Q112. 구어에서 지적이 너무 많지 않나요?
🟢 두 문장 반에 하나꼴(0.397, 하한 ≤0.40)입니다. 대부분 원문의 진짜 오류지만 많다고 느낄 수 있고, **낮출지는 제품 결정**이라고 문서에 적혀 있습니다.
📎 pipeline, README

### Q113. 품질을 어떻게 보장하나요?
🟢 한 명령 `python -m eval.pipeline`이 **단위 테스트 → 모델·사전 대조 → QA 불변식 → 메트릭 하한**을 차례로 돌립니다. 하나라도 실패하면 막힙니다.
📎 책 11장

### Q114. 테스트는 몇 개?
🟢 제 실행에서 **1,020개 통과**(37.6초). README는 997개로 적혀 있습니다(이후 늘어난 것으로 보임).

### Q115. "하한(floor)"이 뭔가요?
🟢 **후퇴 금지선**. 정밀도 ≥0.97, 오탐률 ≤0.002, 과교정률 ≤0.002, 규칙층 재현율 ≥0.97, 혼동쌍 ≥0.99, 로서/로써 ≥0.82. 통과시키려고 **내리지 않습니다.**

### Q116. 하한이 목표인가요?
🟢 아니요. "여기서 더 나빠지면 안 된다"일 뿐 "충분하다"가 아닙니다.
📎 DESIGN 1.8

### Q117. QA 불변식이란?
🟢 어떤 입력에서도 참이어야 하는 성질: 고쳐서 나빠지지 않음(P1), 두 번 고쳐도 같음(P2), 정문에서 high 오탐 0(P3), 고침 폭 최소(P4), 문서 속에서도 같은 결과(P5).
📎 `properties.py`

### Q118. 회귀 레지스트리는요?
🟢 한 번 틀리게 고쳤던 문장을 **영구 등록**해 다시는 안 틀리게 막는 목록(현재 22건, 실패 0).

### Q119. 퍼즈 결과는?
🟢 정문에 무작위 오류를 넣어 검출률을 봅니다. 안/않 100%, 되/돼 94%, 조사 바꾸기 58%, 띄어쓰기 추가 35%, **글자 빠짐 4.6%·글자 중복 3.2%·키보드 7.2%**.
⚠️ 낮은 수치를 숨기지 않습니다. 글자 하나 빠진 오타는 단어를 알아야 잡습니다.

### Q120. 규칙별 오탐률은 왜 재나요?
🟢 전체 오탐률은 규칙 수백 개를 한 숫자로 뭉쳐 결함을 **희석**합니다. `den`은 전체 0.0009일 때 자기 표본에서 0.133이었습니다(148배).
📎 책 11.4

### Q121. 표본이 적으면?
🟢 20건 미만이면 **숫자를 내지 않고 "못 쟀다"**로 표시합니다. 0%와 못 쟀다는 다릅니다.

### Q122. 측정 도구에 버그가 있었나요?
🟢 있었습니다. 공백을 지우는 교정(제안 `""`)을 자동교정으로 세지 않아 붙여쓰기 부류가 29%(실제 79%)로 찍혔고 정밀도도 실제보다 좋게 보였습니다. 고친 뒤 숫자가 나빠졌고 하한은 내리지 않았습니다.
📎 `score.py` 주석, README

### Q123. CI는 돌고 있나요?
🟢 GitHub Actions `quality-pipeline`이 있습니다. 과거 **한 달간 안 돈 적**이 있었고(트리거 브랜치 불일치) 8/30에 고쳤습니다.
📎 DESIGN 2.4
⚠️ 현재 CI 상태는 확인하지 않았습니다.
