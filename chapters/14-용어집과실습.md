# 14장. 용어집, 파일 지도, 직접 해 보기

## 14.1 용어집

가나다 순이 아니라 **이 책에서 처음 등장하는 순서**로 묶었습니다. 장 번호는 처음 설명된 곳입니다.

### 프로그램과 서버 (1, 4장)

| 용어 | 뜻 |
|---|---|
| 변수 | 값에 붙인 이름표 |
| 함수 | 이름 붙인 작업 묶음. 입력을 받아 결과를 돌려줌 |
| 클래스 / dataclass | 관련 값을 묶은 자료 틀. `RawIssue`가 대표 |
| 모듈 / import | 파일 하나가 모듈. 다른 파일의 것을 가져다 씀 |
| 정규식 | "이런 모양의 글자를 찾아라"를 적는 작은 언어 |
| 람다 | 이름 없는 한 줄짜리 함수 |
| 서버 / 클라이언트 | 일을 해 주는 쪽 / 일을 시키는 쪽 |
| API | "이렇게 주문하면 이렇게 답한다"는 약속 |
| 요청 / 응답 | 주문서 / 음식 |
| JSON | 데이터를 글로 적는 형식 `{"이름": 값}` |
| 미들웨어 | 요청이 본 로직에 닿기 전에 지나가는 관문 |
| CORS | 브라우저가 "다른 곳에서 온 페이지의 요청"을 막는 보안 규칙 |
| 레이트리밋 | 한 사용자가 짧은 시간에 너무 많이 요청하는 것을 막기 |
| 캐시 | 한 번 계산한 결과를 저장해 두고 재사용 |
| 422 / 429 / 500 | 주문서 모양 오류 / 요청 너무 많음 / 서버 내부 오류 |

### 한글과 형태소 (2, 3장)

| 용어 | 뜻 |
|---|---|
| 유니코드 | 모든 글자에 번호를 붙여 둔 표 |
| 초성 / 중성 / 종성 | 글자의 첫소리 / 가운뎃소리 / 끝소리(받침) |
| 어절 | 공백으로 나뉜 덩어리 |
| 형태소 | 뜻이나 문법 기능이 있는 가장 작은 조각 |
| 품사 태그 | 형태소의 종류 이름표 (NNG, JKO, VV …) |
| 어간 / 어미 | 활용하는 말의 변하지 않는 부분 / 뒤에 붙는 문법 조각 |
| 조사 | 명사 뒤에 붙는 말 (을/를, 은/는, 이/가, 에게 …) |
| 의존명사 | 혼자 못 쓰고 꾸미는 말 뒤에서만 쓰이는 명사 (것, 수, 뿐 …) |
| 관형사형 어미 (ETM) | 뒤의 명사를 꾸미게 하는 어미 (-ㄴ, -는, -던) |
| 보조용언 | 본용언 뒤에서 도와주는 용언 (-고 있다, -어 주다) |
| Kiwi | 형태소 분석기. 다듬이 빌려 쓰는 외부 라이브러리 |

### 엔진 구조 (5, 6장)

| 용어 | 뜻 |
|---|---|
| 검사기 (checker) | 한 가지 오류 부류를 찾는 함수 |
| 생성기 (generator) | 엔진에 등록된 검사기 (`GENERATORS`) |
| RawIssue / Issue | 지적 한 건. 내부형 / 응답형 |
| 후보 | 아직 정리되지 않은 지적 |
| 병합 (merge) | 겹치는 후보를 우선순위로 하나만 남김 |
| 출처 (source) | 어느 규칙이 낸 지적인가 (`josa_rule` 등) |
| 신뢰도 | high·medium(실선, 클릭 한 번에 고침) / low(점선, 설명만) |
| 가드 | 오탐이 날 자리를 막는 조건 |
| 허용 목록 (allow-list) | 목록에 있는 것만 고치고 나머지는 침묵 |
| 형태소 재조립 | 형태소 목록을 고치고 `kiwi.join`으로 글자로 되돌림 |

## 14.4 직접 해 보기 (실습)

아래 명령은 이 책을 쓰며 제가 같은 방식으로 돌려 본 것들입니다. 환경은 `dadeum/backend`에서 가상환경을 켠 상태입니다.

```bash
cd dadeum/backend
source .venv/bin/activate
```

### 실습 1. 엔진 전체를 한 줄로 돌려 보기

```python
from app.engine import analyze

for r in analyze("학교을 갔다. 그렇게 하면 안되요.").issues:
    print(r.start, r.end, repr(r.original), r.suggestions, r.confidence, r.source)
```

예상: `을 → 를`(josa_rule), `안 되요` 관련 지적들.

### 실습 2. 한 검사기만 따로 돌리기

```python
from app.kiwi_singleton import kiwi
from app.checkers.josa import check_josa

print(check_josa("사과이 맛있다", kiwi))
```

### 실습 3. 형태소 분석 눈으로 보기

```python
from app.kiwi_singleton import kiwi
for t in kiwi.tokenize("학교을 갔다"):
    print(t.form, t.tag, t.start, t.len)
```

3장에서 본 `을/NNG`(조사로 안 읽힘)를 직접 확인해 보세요.

### 실습 4. 받침 계산기

```python
from app.hangul import final_index
for ch in "가각힣교학을밥":
    print(ch, final_index(ch))
```

### 실습 5. 키보드 한 번 실수 판정

```python
from app.keystrokes import keystrokes, one_slip
print(keystrokes("매읽"), one_slip("매읽", "매일"))
print(one_slip("구촌", "구몬"))
```

### 실습 6. 모델이 어느 조각에 힘을 주는지 손으로 계산

```python
from app.checkers.confusion import _MODELS
from app.slots import make_feature, iter_slots

M = {p["name"]: (p, mod, th) for p, mod, th in _MODELS}
pair, model, th = M["doe"]
text = "일이 잘 되면 좋겠다."
for s, e, w in iter_slots(text, "doe"):
    f = make_feature(text, s, e)
    print(f, model.classes_, model.predict_proba([f])[0])
```

7장에서 본 `일이 잘 ▒면 좋겠다.` → `[0.1338, 0.8662]`가 나옵니다(`classes_`는 `['돼', '되']`).

### 실습 7. 규칙을 하나 추가해 보기 (연습)

1. `app/data/dict_rules.json`을 열어 규칙 하나를 복사해 붙입니다.
2. `pattern`을 `(?<=연습 )틀린말`, `replacement`를 `맞는말`로 바꿉니다.
3. `analyze("연습 틀린말")`로 확인합니다.
4. **정문에 걸어 봅니다.** `python -m eval.pipeline`을 돌려 `[per-rule fpr]`과 `[coverage]`에 새 규칙이 어떻게 나오는지 봅니다.
5. 끝나면 `git checkout app/data/dict_rules.json`으로 되돌립니다.

`CONTRIBUTING.md`의 "규칙 하나를 넣는 절차"가 같은 순서입니다(정문에 걸고, 발동을 한 줄씩 읽고, 하한을 내리지 않는다).

## 14.6 맺으며

이 책은 다듬의 구조를 위에서 아래로 따라갔습니다. 정리하면 이렇습니다.

- **큰 그림:** 화면 → 서버 → (분석 → 후보 → 병합) → 화면.
- **후보를 만드는 법 세 가지:** 규칙(사람이 조건을 적음), 모델(예시로 배움), 조언(수상하다고만 말함).
