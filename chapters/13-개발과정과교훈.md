# 13장. 개발 과정과 교훈

앞 장들이 "지금 코드가 어떻게 생겼나"였다면, 이 장은 **"왜 이렇게 생겼나"**입니다.
코드에 남은 이상한 조건 하나하나는 대개 실패의 흔적입니다. 이 장은 그 실패들을 시간 순서로 엮습니다.

근거는 저장소의 git 기록(커밋 377개, 2026-07-14 ~ 2026-09-21)과 `docs/DESIGN.md`입니다.
커밋 제목은 원문 그대로 인용하고, 제 해석은 "해석"이라고 표시합니다.

## 13.2 다섯 번의 큰 방향 전환

### ① 규칙만으로는 안 되는 자리가 있다 → 2층 모델 (7/15)

처음엔 규칙(사전 정규식, 의존명사, 조사)만 있었습니다. `되/돼`는 문맥에 따라 답이 갈려서 규칙을 다 못 적었고, 그래서 7/15에 "혼동쌍 분류기(2층)"를 넣었습니다.
**그리고 AI(Gemini) 3층**도 같은 날 들어왔습니다. "저신뢰 지적을 AI가 재판정"하는 구조였습니다.

### ② 학습형 교정은 안전선을 못 넘었다 (7/24)

"문법 규칙으로 틀린 문장을 합성하고, 그것을 고치는 모델을 학습"하는 시도였습니다. 커밋 기록이 시도와 결론을 그대로 보여 줍니다.

```
Add reliable grammar-driven synthetic GEC data engine + learned-model roadmap
Train an edit-tagging GEC baseline
Document clean-negative sweep: more data alone won't reach the FPR floor
Per-edit-type gating: decisive negative result redirects the strategy
Add 던/든 (den) as a new L2 confusion pair — safe grammar-coverage gain
Document the L2-extension win as the productive local-learning path
```

해석: 모델이 문장을 통째로 고치려면 정문을 건드리지 않는 수준(오탐 하한)을 못 맞췄고, 데이터를 더 넣어도 안 됐습니다. **대신 "좁은 판정(혼동쌍 하나)을 정확히"가 생산적**이라는 결론으로 갔습니다. 이후 학습 모델은 모두 "한 가지 질문에 답하는 작은 판별기"입니다(7장, 8장).

### ③ 상용 서비스를 버렸다 (9/15)

7월 말 레이트리밋·도커·약관·AI 과금·계정·로그인·결제·다운로드까지 만들었다가, 9/15에 **전부 제거**했습니다.

```
feat!: remove the AI layer
feat!: remove billing, accounts, and the service layer
feat: load the shared core in the extension, and drop the service UI
chore: pin dependencies and split production from development
docs: describe the local two-layer engine, and correct the policies
```

해석: "완전 로컬, 외부 API·계정·과금 없음"이라는 지금의 정체성은 **더해서가 아니라 걷어내서** 만들어졌습니다. 이유는 코드에서도 드러납니다. 오탐을 가장 무겁게 보는 이 프로젝트에서 AI의 독자 추측은 통제 밖의 오탐 원천이고, 로컬이라서 개인정보 문제도 사라집니다.

> 이 장의 "해석"입니다. 제거를 결정한 이유가 커밋 메시지에 전부 적혀 있지는 않아서, 위 설명은 코드와 문서 맥락에서 추론한 것입니다.

### ④ "합성 점수"에서 "실사용 점수"로 (9/13)

11장의 93.8% vs 15% 사건입니다. 이 시점에서 개선의 기준이 바뀌었습니다.

```
이전: 합성 오류셋 재현율을 올린다
이후: 사람이 실제로 쓴 오류를 잡는다 (dev·holdout·holdout2)
```

그 결과 다수의 띄어쓰기 규칙이 9/16에 대량으로 들어왔습니다. 모두 "실사용 오류에서 자동교정 0%이던 부류"를 메운 것입니다(`spacing_extra.py`의 첫 설명).

### ⑤ 규칙으로 못 가르는 것은 모델에게 (9/15–9/17)

`runon_boundary` 규칙이 실사용 경계 놓침 36개 중 4개만 잡았을 때, **조건을 더 늘리는 대신 모델을 붙였습니다**(8장 경계 모델). 어절 사전(9장)과 언어모델(9장)도 같은 시기에 같은 이유로 들어왔습니다. "이름이냐 아니냐"는 문법이 아니라 어휘의 문제이기 때문입니다.

## 13.3 15개 원리와 그것을 낳은 실패

`docs/DESIGN.md`는 "원칙만 적으면 다음 사람이 '왜 그렇게까지'라고 생각하며 되돌리기 때문에" **각 원칙에 그것을 낳은 실패를 붙였다**고 씁니다.

| 번호 | 원리 | 낳은 실패 / 근거 |
|---|---|---|
| 1.1 | 과교정이 미탐보다 훨씬 비싸다 | 사용자는 틀리게 고치면 "한 번이면 끈다" |
| 1.2 | 확신이 없으면 표시만 한다 | low를 자동 적용했다면 정문 4.21%를 건드렸다 |
| 1.3 | 아래층의 확신을 위층이 덮지 않는다 | 규칙 > 통계 모델 > AI 추측 |
| 1.4 | 조언은 교정에 양보한다 | `자률신경`을 이상탐지가 통째로 잡아 `률→율` 교정이 탈락 |
| 1.4a | 검사는 하나의 흐름으로 돈다 | 평가가 제품과 다른 코드를 밟아 문체 재현율 0으로 찍힘 |
| 1.5 | 층 하나가 빠져도 앱은 뜬다 | 태거 모델 파일이 없어 앱 전체가 안 뜸, CI가 그렇게 죽음 |
| 1.6 | 그러나 조용히 빠진 것은 반드시 보여야 한다 | CI(태거 없음)와 로컬(태거 있음)이 다른 엔진을 재고 있었음 |
| 1.7 | 규칙은 걸어 보기 전엔 믿지 마라 | `댓가→대가` 앞경계가 재현율만 반토막(0.468→0.968) |

| 1.10-b | 못 잰 것을 0으로 적지 않는다 | 0%와 "못 쟀다"를 숫자로 뭉갬 |
| 1.10-c | 표본을 모은 방식이 분모를 정한다 | 발동 표본으로 재면 정의상 100% (1.000이 과교정률이 아님) |
| 1.10-d | 글자로 안 갈리는 것은 자동 적용하지 않는다 | `에스파냐라고` vs `오냐라고`는 같은 글자 |
| 1.10-e | 사전을 붙이면 될 것 같을 때, 먼저 재 본다 | Kiwi 내장 사전을 붙이면 오탐 5건 줄이려고 탐지 25건 손실 |

| 1.12 | 측정 도구는 제품과 같은 코드를 밟아야 한다 | `run_local`이 일부 검사기를 안 불렀음 |
| 1.13 | 서버가 낼 수 있는 값은 그리는 쪽도 알아야 한다 | `style` 추가 후 웹·확장이 몰라 "5개 발견, 밑줄 4개" |

## 13.4 실패 도감: 실제로 일어난 일 12가지

각 사건은 **무슨 일이 → 왜 못 봤나 → 어떻게 고쳤나** 순서입니다.

### ① `style` 카테고리 500 사건 (8/30)
- **일:** 문체가 섞인 글을 검사하면 서버가 500으로 죽음.
- **왜 못 봤나:** 한 측정은 검사기를 직접 불러(정상), 다른 측정은 API를 거쳐(실패) 두 숫자가 정반대인데 대조하지 않음.
- **해결:** 스키마에 추가 + 계약 테스트(소스를 훑어 모든 카테고리가 스키마·클라이언트에 있는지 대조).
- **후속:** 스키마에 추가하자 웹·확장이 값을 몰라 개수만 세고 밑줄을 못 그림 → 계약 테스트를 클라이언트까지 확장.

### ② 연결어미 `-되` 과교정 (8/30)
- **일:** `적되, 하되`를 `적돼, 하돼`로 medium 신뢰로 고치고 있었음.
- **왜 못 봤나:** 정문 10,000문장에 그 구문이 1건뿐이라 지표가 안 움직임. 오류셋 생성 시 해당 구문 문장이 먼저 소비돼 정문이 남지 않는 구조였음.
- **해결:** Kiwi 품사로 `되/EC`를 구별해 잠금 + **커버리지 게이트** 도입 + 카테고리마다 정문 몫 예약(로서/로써 1건 → 173건).

### ③ `댓가 → 대가` 규칙의 앞경계 (8/30)
- **일:** 오탐을 막으려던 `(?<![가-힣])`가 `공업지댓가`·`전망댓가`를 전부 거부해 사이시옷 재현율이 0.468이었음.
- **해결:** 걷어내니 0.968. 근거는 측정: 위키 18,122문장에 `댓가` 0건, 구어 7건은 전부 오류.
- **교훈:** 그럴듯한 방어도 재 보기 전엔 믿지 않는다(1.7).

### ④ 정문을 고치던 사전 규칙 9개 (9/3)
- **일:** `들께→들게`가 "스님들께", `희안→희한`이 인물 "성희안"을 고치려 듦.
- **왜 못 봤나:** 전체 오탐률 0.0009에 하나도 안 나타남(규칙별 표본이 없었음).
- **해결:** 규칙별 정문 표본 + 검토 대기열 + 단어 경계 조건.

### ⑤ 이상탐지가 교정을 밀어낸 사건 (8/30)
- **일:** `자률신경`을 이상탐지가 어절 통째로 잡아 그 안의 `률→율`이 병합에서 탈락.
- **해결:** 병합에서 "제안 있는 쪽이 먼저".
- **발견자:** 회귀 레지스트리.

### ⑥ 측정 도구가 빈 제안을 못 세던 버그 (9/16)
- **일:** 공백을 지우는 교정(제안 = `""`)을 자동교정으로 세지 않아 붙여쓰기 부류가 29%(실제 79%)로 찍힘. 전체 정밀도·오탐률도 실제보다 좋게 보였음.
- **해결:** 정의 수정 → 숫자가 나빠짐 → 드러난 발동을 전수로 읽어 원문 오류는 오염 목록에, 규칙이 틀린 자리는 규칙을 좁힘. **하한은 하나도 내리지 않음.**
- **교훈:** 측정이 정확해지면 지표가 나빠 보인다. 그건 후퇴가 아니라 진실이 드러난 것.

### ⑦ 한 달간 돌지 않은 CI (8/3~8/30)
- **일:** CI 트리거가 `master`인데 기본 브랜치는 `stable-foundation`이었음. 한 달간 아무 검사도 안 돌았음.
- **해결:** 워크플로 재작성 + 웹 스모크 추가.

### ⑧ torch 없는 CI가 다른 엔진을 재고 있었음 (8/30)
- **일:** `torch`가 requirements에 없어 CI는 태거 없이, 로컬은 태거로 지표를 재고 있었음.
- **해결:** `[layers]` 출력(지표보다 먼저 켜진 층을 찍음).

### ⑨ 리눅스 CI가 맥에서 안 나던 오탐 22건을 잡음 (9/17)
- **일:** 맥에서는 안 나던 정문 발동 22건이 리눅스 CI에서 나옴(원인은 플랫폼에 따른 분석 차이로 보이지만, 저는 확인하지 않았습니다. 같은 날 커밋 제목에 "플랫폼 의존 분석"이 있습니다).
- **해결:** 전수로 읽어 원문 진짜 오류 17건은 오염 목록, 오탐 5건(낙은재·`297조의2`·《짱구는 못말려》)은 규칙을 좁힘.

### ⑩ 무한 피드백 루프 (맥 앱, AXObserver 도입 이후)
- **일:** AX 트리 구성을 매 tick 재요청하면 알림이 다시 일어 tick이 다시 불리는 루프. 대기 중 CPU 10%.
- **해결:** 앱마다 한 번만 요청.

### ⑪ `너무` → `너너무` (맥 앱)
- **일:** 붙여넣기에서 공백이 잘린 채 들어갔는데 값 비교로는 실패처럼 보여 한 번 더 붙여넣음.
- **해결:** 되돌릴 수 없는 동작은 재시도하지 않음 + 공백이 문자열 안쪽에 오게 범위를 넓힘.

### ⑫ 메모리 581MB (8/30)
- **일:** 이상탐지 통계를 dict로 들면 워커 예산(300~500MB)의 3배.
- **해결:** 해시 정렬 배열 + 정수 인코딩 + 압축 캐시 → +54MB.

## 13.5 작업 방식에서 읽히는 공통 습관

이 프로젝트의 커밋과 문서에서 반복해서 나타나는 습관입니다. 해석이 아니라 **관찰**입니다.

1. **고치기 전에 재현한다.** 커밋 메시지에 "실측" 값이 자주 붙습니다.
2. **고친 뒤에 다시 잰다.** 고쳤는데 점수가 나빠지면 그 이유를 적습니다(⑥).
3. **정문을 먼저 지킨다.** 새 규칙은 "오류 회복"과 "정문 오탐" 두 축을 모두 재고 넣습니다.
4. **하한을 내리지 않는다.** 대신 하한 설계가 틀렸으면 바꿉니다(1.9).
5. **안 한 것도 기록한다.** "Tried and rejected" 주석이 코드에 있습니다(숫자 읽기, 겹친 음절, 생물 분류 `속(屬)`).
6. **침묵을 선택으로 둔다.** 못 잡는 것을 억지로 잡느니 점선이나 침묵으로 내립니다.
7. **측정 도구도 코드로 대한다.** 평가 코드의 버그를 엔진 버그만큼 중요하게 다룹니다.
8. **같은 사건이 다시 못 나오게 구조를 바꾼다.** 땜질 대신 계약 테스트·회귀 레지스트리·게이트.
