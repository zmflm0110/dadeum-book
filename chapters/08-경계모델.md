# 8장. 단어 경계 모델 (gyeol-boundary)

"여러 단어를 붙여 쓴 것"(`하는영화`, `나는매일학교가는버스`)을 어디서 끊을지 정하는 모델입니다.
7장의 방식(글자 조각 + 로지스틱 회귀)을 그대로 쓰지만, **누가 후보를 내고 모델은 무엇을 판정하는가**가 다릅니다.
이 장의 값은 모두 제가 코드를 직접 돌려 얻었습니다.

## 8.1 풀려는 문제

붙여 쓴 글을 사람이 읽으면 어디서 끊을지 압니다. 컴퓨터는 어렵습니다.

```
하는영화재밌었다   →   하는 영화 재밌었다
```

Kiwi에는 `kiwi.space(text)`라는 자동 띄어쓰기 기능이 있습니다. 하지만 이 기능은 **한 단어를 억지로 쪼개는** 일이 있습니다.

| 원문 | Kiwi가 제안 | 옳은가 |
|---|---|---|
| 하는영화 | 하는 영화 | ✓ |
| 왔다갔다 | 왔다 갔다 | ✗ (한 단어) |
| 손병호가 | 손 병호가 | ✗ (사람 이름) |
| 도네강과 | 도네 강과 | ✗ (강 이름) |

규칙으로 막으려면 이름·합성어 목록이 끝이 없습니다. 이름이냐 아니냐는 **문법이 아니라 "그 말을 아느냐"**의 문제입니다.
그래서 "Kiwi가 제안한 자리마다, 진짜 단어 경계인지 학습 모델이 판정"하는 구조를 택했습니다.

## 8.2 전체 구조

```
check_boundary(text)                          app/checkers/boundary.py
 │
 ├① 후보 찾기   iter_boundary_candidates()      app/boundary.py
 │   문장별로 kiwi.space() → 원문과 비교 → "붙은 덩어리 안에서 Kiwi가 공백을 넣은 자리"
 │
 ├② 갈래 나누기
 │   · 아주 길게 붙인 덩어리(dense) → 모델 없이 Kiwi를 믿고, 희귀 조각 사이만 버림
 │   · 그 밖                         → 모델이 P(띄움)을 계산, 문턱 0.97 이상만
 │
 ├③ 가드     보조용언 허용 / 의문 어미 / 조문 번호 / Kiwi가 고유명사로 읽은 자리
 │
 └④ 결과     high 신뢰도, 제안 = 그 자리에 공백 하나 넣기
```

**중요:** 후보는 Kiwi만 낼 수 있습니다. 모델은 후보를 **걸러내기만** 하고 새 위치를 만들지 못합니다.
이것은 "모델이 말할 수 있는 범위를 넓히지 않는다"는 안전 설계이기도 하고(오탐이 새로 생길 수 없음), 한계이기도 합니다(Kiwi가 못 본 경계는 영영 못 찾음).

## 8.3 단계 ①: 후보 찾기 (`app/boundary.py`)

### 붙은 덩어리: `runon_spans`

```python
_RUN = re.compile(r"[가-힣0-9A-Za-z]+")      # 한글·숫자·영문이 이어진 구간
MIN_RUNON = 3                                # 3글자 이상

def runon_spans(text):
    return [(m.start(), m.end()) for m in _RUN.finditer(text)
            if m.end() - m.start() >= MIN_RUNON
            and any(_is_hangul(c) for c in m.group())
            and not (m.end() < len(text) and text[m.end()] in _GLOSS_OPENERS)]
```

| 조건 | 이유 |
|---|---|
| 3글자 이상 | 2글자 이하는 붙여 쓴 한 단어일 가능성이 압도적 |
| 한글이 하나라도 있음 | 숫자·영문만의 덩어리는 이 모델 대상이 아님 |
| 바로 뒤가 괄호면 제외 | `민주사회를위한변호사모임(민변)`처럼 **정식 명칭을 일부러 붙여 쓰고** 줄임말을 괄호로 병기하는 한국어 글쓰기 관행 |

한글만이 아니라 숫자·영문도 같은 덩어리로 봅니다. `동독에서는1937년독일국영철도라는`처럼 숫자가 낀 붙여쓰기가 평가에서 놓치는 것의 5분의 1을 차지했기 때문입니다.

### 문장 단위로 돌린다

```python
for (sentence, base), spaced in zip(sentences, kiwi.space([s for s, _ in sentences])):
    if spaced == sentence: continue            # Kiwi가 바꿀 게 없으면 후보 없음
```

**문장 하나씩 따로** 돌립니다. 같은 문장이 혼자 있을 때와 문서 안에 있을 때 Kiwi가 다른 답을 내는 일이 있었기 때문입니다(`그는또한`이 혼자서는 끊기고 문단 안에서는 안 끊김). 사용자가 예측할 수 없는 판정이라 품질 게이트(P5 불변식)가 막습니다.

### 후보 = "원문과 Kiwi 결과의 차이 중 공백 삽입"

```python
for tag, i1, i2, j1, j2 in diff_opcodes(sentence, spaced):
    if tag != "insert" or i1 != i2 or not spaced[j1:j2].isspace(): continue
    if any(lo < i1 < hi for lo, hi in spans):     # 붙은 덩어리 안쪽이면 후보
        yield sentence, i1, base, is_dense
```

`diff_opcodes`는 두 문자열의 차이를 "삽입/삭제/교체" 목록으로 알려 주는 함수(5장 `base.py`)입니다. "공백만 새로 끼워 넣은 것"만 후보로 삼습니다.

## 8.4 단계 ②-a: dense(아주 길게 붙인 덩어리) 판별

### `medial_closures`: "말을 끝맺고도 계속 이어지는" 횟수

한국어 단어는 조사나 어미로 끝납니다. 긴 **이름**은 조사를 맨 끝에만 달지만, **띄어쓰기를 안 하는 사람**의 글은 중간중간 조사·어미가 있고 그 뒤로 또 내용이 이어집니다.

```
조선민주주의인민공화국의         → 조사 '의'가 맨 끝에만 → 0점
나는매일학교가는버스안에서        → '는'(조사) 뒤에 매일…, '는'(어미) 뒤에 버스… → 2점
```

```python
def medial_closures(word, kiwi):
    toks = kiwi.tokenize(word)
    n = 0
    for i, (cur, nxt) in enumerate(zip(toks, toks[1:])):
        tag = cur.tag.split("-")[0]
        if not (tag.startswith("J") or tag.startswith("E")): continue    # 조사·어미가 아니면 패스
        if tag in {"JKG", "ETN"} or nxt가 내용어가 아니면: continue      # 의(속격)·-기(명사형)는 제외
        ...
        n += 1
    return n
```

**제외 두 가지:** `의`(속격)와 `-기`(명사형)는 이름을 만들 때도 쓰입니다(`사랑의책나누기운동본부`). 어절 첫머리의 1음절 동사(`가재울` → `가/VV + 어 + 재우`)는 Kiwi가 이름을 동사로 잘못 읽은 흔적이라 세지 않습니다.

### dense의 정의

```python
DENSE_RUNON_CLOSURES = 2      # 2점 이상
DENSE_RUNON_MIN_LEN = 8       # 8글자 이상
dense = hi - lo >= 8 and medial_closures(...) >= 2
```

길이 조건이 붙은 이유: 실측 오탐이 전부 짧았습니다(`나와틀어은`, `호남절의록은`: 5~6음절). "짧은 어절 안의 조사 두 개"는 흔한 형태소 결합이고, 8글자 이상 되어야 "띄어쓰기를 안 하는 사람"의 글로 볼 수 있습니다.

## 8.5 왜 dense에서는 모델을 안 쓰는가

모델을 돌려 보면 알 수 있습니다. 실제 결과입니다.

```
나는매일학교가는버스안에서 책을 읽었다.     (Kiwi는 다섯 곳을 전부 맞게 띄움)

후보 2   '나는|매일학교가는'        P(띄움)=0.965
후보 4   '나는매일|학교가는버스'    P(띄움)=0.075   ← 진짜 경계인데 거의 0
후보 6   '나는매일학교|가는버스'    P(띄움)=0.276
후보 8   '매일학교가는|버스안에서'  P(띄움)=0.708
후보 10  '학교가는버스|안에서 책을' P(띄움)=0.210
문턱 0.97 → 모델에 맡기면 하나도 못 고침
```

원인은 모델의 한계입니다. 글자 조각(n-gram)을 세는 방식은 "공백이 하나도 없는 문자열 속에서 **이 위치**"를 표현할 수 없습니다. 모든 조각이 주변 70글자의 조각들에 희석됩니다.

해결: **dense 덩어리에서는 모델을 아예 안 쓰고 Kiwi를 믿습니다.** 대신 Kiwi가 알려진 실수를 하는 지점만 막습니다.

## 8.6 dense에서 버리는 자리: `_keep_dense`

Kiwi는 **모르는 말을 만나면 한 음절씩 쪼갭니다.** 그러면 `핡교`가 `핡 교`가 됩니다. 이건 도움이 안 됩니다. `핡교`로 두면 최소한 오타로 읽힙니다.

```python
edges  = [lo, *positions, hi]
pieces = [sentence[a:b] for a, b in zip(edges, edges[1:])]
rare   = [not _is_word(p) for p in pieces]          # 사전에서 단어로 보이지 않는 조각
# 양옆 조각이 둘 다 희귀한 경계만 버린다
return {p for i, p in enumerate(positions) if not (rare[i] and rare[i + 1])}
```

### 조각이 "단어"인지: `_is_word`

```python
_PIECE_FLOOR_SYLLABLE = 1000     # 한 음절 조각: 사전에서 1,000번 이상 나와야 단어
_PIECE_FLOOR = 1                 # 두 음절 이상: 한 번이라도 나오면 단어
```

| 조각 | 길이 | 사전 빈도 | 단어? |
|---|---|---|---|
| 수 | 1 | 293,000회 | ✓ |
| 때 | 1 | 68,000회 | ✓ |
| 교 | 1 | **59회** | ✗ (1,000 미만) |
| 핡 | 1 | 0회 | ✗ |
| 완주군 | 3 | 225회 | ✓ |

한 음절은 어디에나 있어서 기준을 높게, 두 음절 이상은 존재만 해도 단어로 봅니다.
실제 결과(어절 사전 181만 어절을 직접 조회):

```
나는매일핡교가는버스안에서 책을 읽었다.
Kiwi:    나는 매일 핡 교 가는 버스 안에서
사전:    핡=0, 교=59 (둘 다 희귀)
결과:    나는 매일 핡교 가는 버스 안에서    ← '핡|교' 경계만 안 끊음
```

(실제 최종 `check_boundary` 출력은 `(2 매), (4 핡), (6 가), (8 버), (10 안)`입니다. `핡`과 `교` 사이 5번 자리는 제안되지 않습니다.)

## 8.7 단계 ②-b: 모델 판정 (dense가 아닐 때)

### 특징 만들기

```python
WINDOW = 10
MARKER = "▣"

def make_boundary_feature(text, pos):
    left  = text[max(0, pos - WINDOW) : pos]
    right = text[pos : pos + WINDOW]
    return f"{left}{MARKER}{right}"
```

```
"어제 하는영화 재밌었다."  후보 위치 5  →  "어제 하는▣영화 재밌었다."
```

7장의 `▒`는 **정답을 가리는** 표시였습니다. 여기 `▣`는 **"여기가 후보 자리"라고 알려 주는** 표시입니다(끊을지 말지가 정답이므로 가릴 글자가 없습니다).

### 판정

```python
if not dense and proba[space_col] < threshold:     # 문턱 0.97
    continue
```

7장과 같은 방식(2~4글자 n-gram + TF-IDF + 로지스틱 회귀)으로 `P(띄움)`을 구해 0.97 이상일 때만 통과시킵니다.

## 8.9 학습 데이터 만들기 (`ml/boundary_data.py`)

7장과 같은 발상입니다: **정문에서 문제와 정답을 동시에 만든다.**

```
원문(위키):   흐르고 도네강과                 ← 띄어쓰기가 맞는 문장
붙이기:       흐르고도네강과                 ← 일부러 이웃 단어를 붙임
Kiwi 후보:    3번 자리(흐르고|도)  → 원래 이음매였음 → 정답 "space"
              6번 자리(도네|강)    → 원래 한 단어    → 정답 "join"
```

### 만드는 규칙

- 문장마다 이웃한 **2~3단어를 붙인 곳을 최대 4개** 만듭니다.
- 3어절 이상이고 전부 한글인 문장은 **문장 전체를 붙인 것**도 하나 더 만듭니다(`_WHOLE_SENTENCE_MIN_WORDS = 3`).
- 붙이지 않은 어절 안에서 Kiwi가 끊자고 한 자리도 **"join"(끊지 마)**으로 씁니다. 위키는 편집된 글이라 그 어절은 원래 맞게 붙어 있다고 보는 것입니다. 이것이 `도네강`·`해선리` 같은 **어려운 오답 사례**입니다.

> 이 "어려운 오답"을 빼 보았더니, 같은 오탐률을 지키는 문턱이 0.97에서 0.995로 올라가서 이 층이 사실상 아무 일도 안 하게 됐다는 기록이 코드에 있습니다.

### 시험 문제 미리 보기 방지

```python
excluded = _eval_sentences()          # 평가에 쓰는 모든 문장
rows = [(s, c) for s, c in rows if s not in excluded]
```

평가셋(`real_errors`, `corpus_suite`)에 있는 문장은 학습에서 **정확히 같은 문장이면 뺍니다.**

### 구어 코퍼스를 끈 이유

nsmc(영화 리뷰) 6만 2천 문장을 넣어 봤더니 학습 행이 31만에서 79만으로 늘었는데, 같은 문턱에서 **정상 문장을 잘못 끊는 비율이 15배**(`.00021 → .00327`)가 됐고 실사용 재현율은 그대로(126건)였습니다. 구어는 "정문"이라고 해도 두 문장 중 한 문장 꼴로 띄어쓰기가 빠져 있어 "join" 정답이 오염되기 때문입니다. 기본값은 꺼짐입니다.

### 결과 규모

학습 141,388행, 시험 15,977행. 정답 비율은 `join` 62.7%.

## 8.10 학습과 문턱 고르기 (`ml/train_boundary.py`)

방식은 7장과 같지만 **예산이 둘**입니다.

| 예산 | 값 | 무엇을 재나 |
|---|---|---|
| `FP_BUDGET` | 0.01 | 시험 후보 중 "join"을 잘못 띄우는 비율 |
| `SENTENCE_FP_BUDGET` | 0.0005 | **손대지 않은 정문 문장**(3,169개)에서 한 군데라도 끊기는 문장의 비율 |

두 번째가 더 중요합니다. 첫 번째만 쓰면 "붙여 놓은 쌍"이라는 쉬운 분포에서 잰 값이라 실제 문장에서 오탐이 세 배가 됐습니다. 그래서 **진짜 정문 문장을 통째로 넣어서** 재는 예산을 따로 둡니다.

`0.0005`는 임의의 숫자가 아닙니다. 제품 전체 오탐 하한이 0.002인데 규칙 층들이 이미 0.0017을 쓰고 있어서, **새 층에 남은 몫**이 이만큼입니다.

### 문턱 표 (실제 `boundary_meta.json`)

| 문턱 | 후보 단위 오탐 | 진짜 경계 재현 | 문장 단위 오탐 |
|---|---|---|---|
| 0.5 | 17.6% | 89.0% | 12.5% |
| 0.7 | 4.7% | 74.6% | 3.9% |
| 0.8 | 1.4% | 62.0% | 1.1% |
| 0.9 | 0.28% | 39.7% | 0.28% |
| 0.95 | 0.10% | 18.9% | 0.063% |
| **0.97 ← 채택** | **0.05%** | **9.3%** | **0.032%** |
| 0.99 | 0% | 1.6% | 0% |

**문턱 0.95는 문장 오탐 0.063%로 예산 0.05%를 넘어서 탈락**, 0.97이 처음 두 예산을 모두 지킵니다.

### 숫자를 읽는 법

- README의 "정확도 86.54%"는 문턱 0.5 근처의 값입니다.
- **실제 쓰는 문턱 0.97에서는 진짜 경계의 9.3%만 모델 혼자 고칩니다.**
- 즉 이 모델은 "많이 잡는 모델"이 아니라 **"아주 확실한 것만 잡고 나머지는 침묵하는 모델"**입니다. 이 프로젝트의 원칙(오탐 공포)이 그대로 드러난 설계입니다.

## 8.12 한계 (코드에 적힌 실측 기록)

1. **걸러내기 전용입니다.** Kiwi가 제안하지 않은 경계는 찾지 못합니다.
2. **8글자 미만으로 길게 붙인 문장이 사각지대입니다.** dense 기준에 못 미쳐서 모델에 넘어가는데, 모델은 0.97을 거의 못 넘깁니다.
3. **데이터를 늘려도 나아지지 않았습니다.** 5번 재학습하며 위키를 5만 1천 → 9만 8천 문장으로, 구어 6만 2천을 더했지만 실사용 재현율은 제자리(dev 220–227/356, holdout 121–126/204)였습니다. 데이터가 많을수록 문장 오탐 추정이 정확해져 문턱이 올라가고, 얻은 만큼 도로 잃기 때문입니다.
4. **품사 태그를 특징에 넣어도 이득이 없었습니다.** 오프라인 재현율이 0.155 → 0.367로 올랐지만 그 문턱(0.97)에서 정문 12건을 잘못 끊었고(`경기도|리그`, `동음이|의`), 쓸 수 있는 문턱(0.99)에서는 태그 없는 모델과 같았습니다. "오프라인 곡선이 실사용을 따라가지 않는다"는 것이 교훈입니다.
5. **한계는 데이터가 아니라 모델의 종류**에 있습니다. 코드의 기록: 문장 전체를 붙인 샘플을 더해도 `나는매일|학교`의 점수가 0.056 → 0.094밖에 안 올랐습니다. 글자 조각 세기 방식으로는 "공백 없는 긴 문자열 속의 위치"를 표현할 수 없습니다. 샘플은 "다음 모델 종류를 위해 남겨 둔다"고 적혀 있습니다.
