# 12장. 화면과 공유 코어

서버는 "어디가 틀렸나"만 답합니다. 사용자가 보는 **밑줄, 카드, 고치기, 되돌리기**는 화면 쪽 코드입니다.
화면은 세 종류(웹·크롬 확장·맥 앱)이고, 언어도 JavaScript 둘과 Swift 하나입니다.
이 장은 세 화면이 **같은 일을 어떻게 나눠 갖는지**, 그리고 그 공통 부분인 **공유 코어**를 설명합니다.

> 이 장의 `node` 테스트 결과(30개 통과)는 제가 직접 돌린 값이고, 맥 앱·확장·웹의 동작은 코드를 읽은 내용입니다. 맥 GUI와 크롬 확장은 이 대화에서 직접 실행해 보지 않았습니다.

## 12.1 세 화면이 공통으로 해야 하는 일

```
① 글을 읽는다            (웹: textarea / 확장: 웹 입력창 / 맥: 다른 앱의 입력창)
② 서버에 묻는다          POST /api/check
③ 밑줄을 그린다          issues[] 의 start~end 위치에
④ 사용자가 고친다        밑줄 클릭 / 카드 / 모두 고치기
⑤ 위치를 다시 맞춘다     하나를 고치면 뒤쪽 위치가 밀림
⑥ 무시·되돌리기를 기억한다
```

**①③④는 화면마다 완전히 다릅니다.** 웹은 DOM, 확장은 남의 웹페이지, 맥은 접근성(AX) API를 씁니다.
**②는 모두 같고, ⑤⑥은 "상태 관리"라서 화면과 상관없이 같은 로직입니다.** 이 공통 부분을 한 곳에 모은 것이 코어(`core/issue-session.mjs`)입니다.

## 12.2 왜 공유 코어가 생겼나

> 이 상태 로직이 웹·확장·데스크톱에 **3중 독립 구현**되어 서로 어긋났습니다. 한 곳의 버그 수정이 다른 곳에 가지 않았습니다.
> 클라이언트 쪽 자동 테스트는 없었습니다. (코어를 도입하기 전의 감사 기록 요약. 코드에서 직접 확인한 것은 아닙니다.)

3중 복사를 한 곳으로 모으고, **한 번 명세해서 두 언어로 포팅한 뒤 같은 시나리오 테스트를 통과하게** 했습니다.

| 파일 | 언어 | 사용처 |
|---|---|---|
| `core/issue-session.mjs` | JavaScript (원본) | 웹 앱이 ES 모듈로 import |
| `extension/core.generated.js` | JavaScript (생성물) | 확장. MV3 콘텐츠 스크립트는 `import`를 못 해서 원본을 변환해 만듦 |
| `desktop/Sources/IssueSession/IssueSession.swift` | Swift (포팅) | 맥 앱 |
| `core/bundle-parity.test.mjs` | 테스트 | 원본과 생성물의 동작이 같음을 증명 |

> 현재 확장은 코어의 일부(`signature`, `isActionable`, `isIgnored`)만 씁니다. 교정 적용·위치 이동은 아직 `content.js`의 자체 구현입니다(README "한계" 표에도 적혀 있음).

## 12.3 코어의 설계 규칙 (파일 맨 위 설명)

| 규칙 | 뜻 |
|---|---|
| **순수 함수** | DOM·AppKit·fetch를 모릅니다. "옛 상태를 받아 새 상태를 돌려준다". 입력을 절대 안 고칩니다 |
| **코드포인트 기준** | 모든 위치가 유니코드 코드포인트 번호입니다. 이모지 하나가 JS에서는 2칸이지만 코어에서는 1칸 |
| **안정적인 `sid`** | 서버의 `id`는 재검사할 때마다 바뀌므로 코어가 자기 번호를 붙여 유지 |
| **영구 무시** | "무시"는 `원문|제안` 서명으로 기억해서 재검사해도 되살아나지 않음 |
| **개인 사전** | 단어 단위로 허용. `손병호`를 등록하면 `손병호가`, `손병호를`도 침묵 |

### 상태의 모양

```js
function createSession() {
  return {
    text: "",           // 지금 글
    issues: [],         // 지금 보이는 지적들
    dismissed: [],      // 무시한 서명들 ("원문|제안")
    ignoredWords: [],   // 개인 사전
    undoStack: [],      // 되돌리기 스택 (최대 50)
    nextSid: 1,         // 다음에 붙일 고유번호
  };
}
```

## 12.4 코어 함수 하나씩

### `signature(issue)`: 지적의 정체성

```js
export function signature(issue) {
  return `${issue.original}|${issue.suggestions[0] || ""}`;
}
```

`을|를`처럼 **무엇을 무엇으로**가 곧 정체성입니다. 위치는 정체성이 아닙니다. 위치는 글이 바뀌면 바뀌기 때문입니다. "무시"를 이것으로 기억하므로, 같은 교정이 다른 곳에서 다시 나와도 같이 무시됩니다.

### `isActionable(issue)`: 한 번에 고칠 수 있나

```js
export function isActionable(issue) {
  return issue.suggestions.length > 0 && issue.confidence !== "low";
}
```

**제안이 있고 low가 아닐 때만** "클릭 한 번에 고침"입니다. low는 "한번 봐 보세요"이고 자동으로 안 고칩니다. 서버의 신뢰도가 화면의 행동으로 바뀌는 지점입니다.

### `setResults(state, text, rawIssues)`: 서버 응답 받기

```js
const kept = rawIssues.filter(
  (r) => !dismissed.has(signature(r)) && !wordIsIgnored(wordAt(text, r), ignored));
const { issues, nextSid } = assignSids(state, kept);
return { ...state, text, issues, undoStack: [], nextSid };
```

1. 무시한 서명과 개인 사전 단어를 걸러 냅니다.
2. 남은 것에 `sid`를 붙입니다.
3. **되돌리기 스택을 비웁니다**(새 검사는 새 기준점).

### `applyFix`: 하나 고치기 (가장 중요한 함수)

```js
const cps = [...state.text];                           // 코드포인트 배열
const newText = cps.slice(0, issue.start).join("") + suggestion + cps.slice(issue.end).join("");
const delta = cpLen(suggestion) - (issue.end - issue.start);
const issues = state.issues
  .filter((o) => o.sid !== sid)                              // ① 방금 고친 것 제거
  .filter((o) => o.start >= issue.end || o.end <= issue.start)   // ② 고친 자리와 겹치는 것 제거
  .map((o) => (o.start >= issue.end ? { ...o, start: o.start + delta, end: o.end + delta } : o)); // ③ 뒤쪽 이동
return { ...state, text: newText, issues, undoStack: pushUndo(state) };
```

**세 단계:**

1. 고친 지적을 지적 목록에서 뺍니다.
2. 고친 자리와 **겹치는** 다른 지적은 이제 낡은 것이라 버립니다(그 자리의 글자가 바뀌었으므로).
3. 고친 자리 **뒤에 있는** 지적은 `delta`(고친 뒤 길이 − 원래 길이)만큼 위치를 이동합니다.

`delta`가 핵심입니다. 실제 예:

```
글:     "학교을 갔다 안되요"
고침:   '을' → '를'    (길이 1 → 1, delta = 0)    뒤 지적 위치 변화 없음
고침:   '안' → '안 '   (길이 1 → 2, delta = +1)   '되요' 위치 25→26 처럼 +1
```

**`delta`가 없으면** 뒤쪽 밑줄이 엉뚱한 글자 위에 그려집니다. 실제로 이모지가 포함된 글에서 위치가 어긋나 밑줄·교정이 다른 자리로 간 버그(7/16 "Fix mark misplacement/text corruption when text contains emoji")가 있었고, 코드포인트 기준으로 통일하며 고쳤습니다.

#### 방어 코드

```js
if (!issue) return state;               // 이미 사라진 지적(오래된 클릭)이면 아무것도 안 함
if (suggestion == null) suggestion = issue.suggestions[0];
if (suggestion == null) return state;   // 제안이 아예 없으면(저신뢰 검토용) 글자에 "undefined"를 넣지 않는다
```

마지막 줄은 실제 사고의 흔적입니다(2026-08-04 "fix(core): applyFix 제안 생략/부재 시 크래시 방지 (500문장 퍼징 발견)").

### `applyAll`: 모두 고치기

```js
let next = { ...state, undoStack: pushUndo(state) };       // 되돌리기 한 번에 묶음
let guard = 500;
while (guard-- > 0) {
  const target = next.issues.filter(isActionable).sort((a, b) => a.start - b.start)[0];
  if (!target) break;
  const withoutPush = applyFix({ ...next, undoStack: [] }, target.sid, target.suggestions[0]);
  next = { ...withoutPush, undoStack: next.undoStack };
}
```

- 실선(고칠 수 있는 것)만, **앞에서부터 하나씩** 적용합니다.
- 매번 `applyFix`가 뒤쪽 위치를 다시 밀어 주므로 순서가 안전합니다.
- 전체를 **한 번의 되돌리기**로 묶습니다.
- `guard = 500`: 무한 루프 방지 안전장치입니다.

#### 직접 돌려 본 결과

```
자동 적용 대상: 을, 안, 되요, 든, 많
모두 고치기 후: 학교를 가는길에 친구를 만낫는데 그렇게 하면 안 돼요. 매읽 그 영화 봤던 사람이 너무 많아서 놀랐다.
남은 점선:      길@6, 만낫는데@13, 매읽@31
```

점선 셋(길, 만낫는데, 매읽)은 그대로 남았고, `매읽`의 위치가 30에서 **31**로 이동했습니다(앞의 `안` → `안 `으로 한 글자 늘어서).

### `dismiss`, `ignoreWord`, `forgetWord`, `undo`

| 함수 | 하는 일 |
|---|---|
| `dismiss` | 서명을 `dismissed`에 넣고 목록에서 뺌. **글은 안 건드림.** 되돌리기 가능 |
| `ignoreWord` | 지적이 걸린 어절에서 조사를 떼어(`손병호가`→`손병호`) 개인 사전에 넣고, 그 단어가 걸린 모든 지적을 뺌 |
| `forgetWord` | 사전에서 뺌. 다음 검사 때 다시 지적됨 |
| `undo` | 스택 맨 위의 `{text, issues}`로 복원 (최대 50단계) |

#### `entryFor`: 사전에는 "단어"를 넣는다

엔진은 `손병호`의 `병` 자리를 지적합니다. 사용자가 "이 단어 허용"을 누르면 **지적 위치**가 아니라 **그 어절**이 사전에 들어가야 합니다.

```js
const TRAILING_PARTICLES = ["으로서", "으로써", ..., "은", "는", "이", "가", "을", "를", ...];
```

어절 끝의 조사를 떼서 단어만 저장합니다. 그래서 `손병호가`를 눌러도 `손병호`가 저장되어 `손병호를`, `손병호에게`까지 덮입니다.

주의가 있습니다. **한 음절 조사를 떼면 두 음절이 남는 경우(`경기도`→`경기`)가 위험**합니다(`경기장`, `경기력`까지 침묵하게 됨). 그래서 한 음절 조사를 뗄 때는 **남는 말이 3음절 이상**일 때만 떼고, 여러 음절 조사는 2음절 이상이면 뗍니다(`MIN_STEM_AFTER_SHORT_PARTICLE = 3`).

#### 사전 항목은 접두사로 매칭

```js
function wordIsIgnored(word, ignoredWords) {
  return word.length > 0 && ignoredWords.some((w) => w.length >= 2 && word.startsWith(w));
}
```

한국어는 조사가 오른쪽에 붙으므로 `손병호`는 `손병호`로 **시작하는** 모든 형태를 덮습니다.

### 되돌리기

```js
function pushUndo(state) {
  return [...state.undoStack, { text: state.text, issues: state.issues.map(i => ({...i})) }].slice(-MAX_UNDO);
}
```

**상태 전체를 복사해서** 쌓습니다(`{...i}`로 한 겹 복사). 순수 함수 설계라서 "되돌리기 = 이전 스냅샷으로 교체"가 가장 단순하고 안전합니다. 최대 50개에서 오래된 것을 버립니다.

## 12.5 두 언어로 같은 코드

Swift 포팅(`IssueSession.swift`)은 같은 구조(`undoStack`, `pushSnapshot`, 적용·전체 적용·무시)를 가집니다. JS 쪽 주석은 `MAX_UNDO`가 "Swift 포트와 일치해야 한다"고 적고 있습니다(Swift 쪽 상수 이름과 값은 제가 확인하지 않았습니다). 같은 시나리오를 양쪽 테스트(JS 30개, Swift 별도 테스트 실행 파일)가 검증합니다.

```
$ node --test core/*.test.mjs
ℹ tests 30   ℹ pass 30   ℹ fail 0
```

JS 쪽 30개는 제가 돌려서 모두 통과했습니다. Swift 테스트는 이 대화에서 실행하지 않았습니다.

## 12.6 웹 앱 (`frontend/app.js`, 880줄)

바닐라 JS(프레임워크 없음)이고 `core/`를 ES 모듈로 import합니다.

### 자동 검사의 시간표

```js
const AUTO_CHECK_PASTE_MS    = 400;   // 붙여넣기 직후
const AUTO_CHECK_TYPING_MS   = 700;   // 타이핑을 멈춘 뒤
const AUTO_CHECK_BOUNDARY_MS = 250;   // 단어/문장이 방금 끝났을 때
const AUTO_CHECK_SYLLABLES   = 6;     // 경계 없이 6음절 늘었을 때
const AUTO_CHECK_MAX_WAIT_MS = 900;   // 어떤 경우에도 이 이상은 안 기다림
```

**왜 이렇게 복잡한가:** 단순 디바운스(마지막 입력 후 N초)는 계속 타이핑하는 동안 **영원히 안 돕니다.** 키를 누를 때마다 타이머가 밀리기 때문입니다. 실제로 "다 써야 동작한다"는 불만이 있었습니다. 그래서 "최대 대기 0.9초"를 둡니다.

(README는 "타이핑 정지 1.5초"라고 적었지만 코드는 0.7초입니다. 코드가 최신입니다.)

### 낡은 응답 버리기: 세대 번호

```js
const generation = requestGeneration;          // 보낼 때의 번호
const data = await postJSON("/api/check", { text });
if (generation !== requestGeneration) return;  // 그 사이 새 검사가 시작됐으면 버림
```

응답이 **보낸 순서대로 오지 않을 수** 있습니다. 느린 응답이 늦게 도착해서 최신 결과를 덮어쓰면 안 됩니다. 요청마다 번호를 매기고 "내 번호가 최신일 때만" 반영합니다.

### 타이핑 중 응답이 도착하면

```js
const live = input.value;
if (live !== text && !live.startsWith(text)) return;    // 중간을 고쳤다면 위치가 어긋나므로 버림
```

응답이 오는 동안 사용자가 **글 끝에 더 쓴 것뿐**이라면 위치가 그대로 유효합니다(`startsWith`). 중간을 고쳤다면 위치가 어긋났으므로 버립니다.

### 밑줄이 유지되는 조건: `marksSurvive`

타이핑할 때마다 밑줄을 지우면 깜빡입니다. 그래서 **모든 지적이 바뀐 곳보다 앞에 있으면** 유지합니다(마지막 지적의 끝까지가 이전 글과 같은지 비교).

```js
const lastEnd = Math.max(...issues.map((i) => i.end));
for (let i = 0; i < lastEnd; i++) if (cps[i] !== nextCps[i]) return false;
return true;
```

### 화면 좌표: 코드포인트 → UTF-16

코어는 코드포인트, DOM은 UTF-16이라서 화면에 그릴 때만 변환합니다(`cpToU16Map`).

### 상한

웹 앱은 **5,000자**(`MAX_TEXT_LEN`)에서 막지만 서버는 2만 자까지 받습니다. 두 값이 어긋나 있습니다.

## 12.7 크롬 확장 (`extension/`, MV3)

### 구성

| 파일 | 역할 |
|---|---|
| `manifest.json` | 권한·주입 대상 선언 |
| `background.js` (41줄) | **서비스 워커.** 서버 호출을 대행 |
| `content.js` (1,271줄) | 웹페이지에 주입. 입력창 감지·밑줄·카드 |
| `popup.*`, `options.*` | 설정 화면 |
| `core.generated.js` | 공유 코어 생성물 |

### 왜 서버 호출을 서비스 워커가 하나

```js
// background.js
const res = await fetch(`${base}/api/check`, { method: "POST",
  headers: { "Content-Type": "application/json", "X-Dadeum-Client": "extension" },
  body: JSON.stringify({ text: msg.text }) });
```

웹페이지에 주입된 스크립트는 **그 페이지의 보안 정책(CSP/CORS)을 그대로 받습니다.** 어떤 사이트는 외부 서버 연결을 막아 두었습니다. 서비스 워커는 확장 자신의 권한(`host_permissions`)으로 호출하므로 어느 사이트에서도 됩니다. 콘텐츠 스크립트는 `chrome.runtime.sendMessage`로 워커에게 부탁합니다.

### 두 종류의 입력창

| 종류 | 대상 | 밑줄 방식 | 고치는 방식 |
|---|---|---|---|
| value 필드 | `textarea`, `input` | 같은 크기·글꼴의 **거울 div**를 위에 겹쳐서 글자는 투명, 오류 부분만 아랫줄 | `setRangeText()` |
| 편집 가능 루트 | `contentEditable`, `role=textbox` (유튜브 댓글, 지메일) | `Range.getClientRects()`로 좌표를 구해 **띠(strip)**를 절대 위치로 | 범위 선택 후 `execCommand("insertText")` |

두 오버레이 모두 `pointer-events: none`이라 **타이핑·클릭을 가로채지 않습니다.**

### 한글 입력의 철칙

```
compositionstart ~ compositionend 사이에는 절대 건드리지 않는다
```

한글은 자모를 쳐서 글자를 **조합**하는 동안 입력기가 글자를 임시로 갖고 있습니다. 그 사이에 글을 바꾸면 입력이 깨집니다. 코드는 조합 중이면 `check()`를 건너뜁니다(`if (!enabled || st.composing) return;`).

### 확장이 자기를 알리는 이유 (4장)

모든 요청에 `X-Dadeum-Client: extension`을 붙여서, 서버가 "확장이 살아 있다"를 기억하고 맥 앱이 이를 읽어 크롬에서 비켜섭니다.

## 12.8 맥 앱 (`desktop/`, Swift)

### 접근성(AX) API란

macOS는 다른 앱의 화면 요소(버튼, 입력창 등)를 **프로그램이 읽고 조작**할 수 있는 접근성 API를 제공합니다(원래 시각 장애인을 위한 기능). 사용자가 "손쉬운 사용" 권한을 주면 다듬은 다른 앱의 입력창 글자를 읽을 수 있습니다.

| 하는 일 | AX 속성 |
|---|---|
| 지금 포커스된 입력창 찾기 | 최전면 앱 → `AXFocusedUIElement` |
| 글 읽기 | `kAXValueAttribute` |
| 글자 위치의 화면 좌표 | `kAXBoundsForRangeParameterizedAttribute` |
| 범위 선택 | `kAXSelectedTextRangeAttribute` |
| 교체 | `kAXSelectedTextAttribute`에 쓰기 |

### 전체 흐름

```
AXObserver(변화 알림)  →  tick()  →  글이 바뀌었나?
                                  →  scheduleCheck(0.25초 디바운스)  →  POST /api/check
                                  →  setResults (공유 코어)
                                  →  redraw: 각 지적의 화면 좌표를 구해 밑줄 창에 그림
```

### 폴링 대신 이벤트 구독

처음엔 0.25초마다 폴링(계속 물어보기)했지만, `AXObserver`로 **변화가 있을 때만** 알림을 받도록 바꿨습니다. 구독하는 알림: 포커스 요소 변경, 값 변경(타이핑), 선택 변경, 창 이동·크기 변경. 대기 중 CPU 약 0.7%(README)입니다.

#### 실제 사고: 무한 피드백 루프

코드 주석입니다. AX 트리 구성을 요청하는 속성(`AXManualAccessibility`)을 **매 tick마다** 다시 쓰면, 일부 앱이 트리를 매번 재구성하고 그것이 `AXValueChanged` 알림을 다시 일으켜 `tick()`을 또 부르는 **무한 루프**가 됐습니다(실측: 대기 상태에서 3초에 알림 136개, CPU 약 10%). 그래서 앱마다 **딱 한 번만** 요청합니다(`_a11yConfigured`).

### 교정 적용: `applyCorrection`

AX는 "다른 프로세스의 입력창을 고치는" 일이라 가장 까다롭습니다. 코드의 방어가 단계별로 있습니다.

```
① 쓰기 전에 그 자리에 정말 그 글자가 있는지 확인   (오프셋이 어긋난 채 쓰면 엉뚱한 곳을 덮어씀)
② 공백으로 시작/끝나는 교정은 범위를 한 글자 넓힘   (붙여넣기에서 앞뒤 공백을 버리는 앱이 있음)
③ 1순위: 범위를 선택하고 kAXSelectedText 에 씀
④ 결과가 "값이 바뀜"이 아니라 "기대한 결과와 같은가"를 확인
⑤ 0.35초 뒤 한 번 더 확인 (앱이 되돌리는 경우: 자동완성, IME 조합 커밋)
⑥ 2순위 폴백: 클립보드에 넣고 선택 후 Cmd+V → 반영 확인 후 클립보드 원복
⑦ 폴백은 절대 재시도하지 않음
```

⑦의 사연: 처음엔 "실패로 보이면 한 번 더 붙여넣기"를 했는데, 첫 붙여넣기가 (공백이 잘린 채로) 이미 들어가 있어서 **`너무`가 `너너무`**가 됐습니다. 코드 주석: "되돌릴 수 없는 동작은 재시도하지 않는다."

②의 예: `[너]`를 `' 너'`로 바꾸려는데 앱이 앞 공백을 버리면 `너`가 되어 아무 일도 안 일어난 것처럼 보입니다. 그래서 옆 글자를 물고 가서 `[이너]` → `'이 너'`로 만들어 공백이 문자열 안쪽에 오게 합니다.

### 안전 장치

| 장치 | 이유 |
|---|---|
| 비밀번호 필드(`AXSecureTextField`) 제외 | 보안 |
| `IsSecureEventInputEnabled()`가 참이면 `nil`을 돌려줌(`main.swift:168`) | 비밀번호 입력 등 보안 입력 모드에서는 읽지 않음 |
| 터미널·코드 에디터·콘솔 앱은 인라인 교정 끔 | 화면 출력 전체가 오류로 잡힌 적 있음(2026-08-05) |
| 크롬 계열 브라우저는 확장이 살아 있을 때만 비켜섬 | 배지 두 개 겹침 방지 |
| 밑줄 좌표가 입력창 프레임 밖이면 버림 | Chromium이 `(0,956)` 같은 쓰레기 좌표를 줌 |
| `AXBoundsForRange` 미지원 앱은 밑줄 없이 맞춤법 검사 창(⌃⌥D)으로만 | 좌표를 못 구하는 앱 |

### 오류 코드를 버리지 않는다

```swift
func axErrName(_ e: AXError) -> String {
    case .apiDisabled: return "apiDisabled(손쉬운 사용 권한 거부됨)"
    case .attributeUnsupported: return "attributeUnsupported(이 앱이 안 주는 속성)"
```

"권한이 없어서 못 읽는다"와 "이 앱은 원래 이 속성을 안 준다"가 로그에서 똑같이 보이면, 앞의 경우(앱 전체가 죽은 것)를 뒤의 경우(그 앱만 빠지는 것)로 오진합니다. 실제로 한참 헤맸다는 기록이 주석에 있습니다.
