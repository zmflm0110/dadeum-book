# 6장. 규칙 검사기: 문법을 코드로 옮긴 것들

이 장은 모델(학습)이 아니라 **사람이 규범을 읽고 코드로 옮긴 규칙**을 다룹니다.
"같은 입력이면 늘 같은 출력"이라 이해하기 쉽고, 그만큼 **예외 처리**가 코드의 대부분입니다.
이 장의 모든 실행 결과는 제가 검사기 함수를 직접 불러 얻은 값입니다.

## 6.0 규칙 검사기의 공통 설계

거의 모든 검사기가 같은 세 단계를 밟습니다.

```
① 후보 찾기   : 형태소 태그나 정규식으로 "여기가 의심스럽다"를 찾는다
② 함정 거르기 : 오탐이 날 만한 자리를 allow-list / frame / 가드로 제외한다
③ 지적 만들기 : RawIssue 를 만든다 (필요하면 kiwi.join 으로 고친 말을 조립)
```

코드를 읽을 때 **분량의 80%는 ②**입니다. ①은 보통 서너 줄이고, ②에 "이런 경우는 정문이다"라는 실측 사연이 줄줄이 붙어 있습니다.
이 프로젝트에서 규칙을 쓰는 일은 "규칙을 만드는 일"이 아니라 **"규칙이 틀리게 발동하는 자리를 하나씩 막는 일"**입니다.

### 공통 부품

| 부품 | 위치 | 역할 |
|---|---|---|
| `tokenize_cached(kiwi, text)` | `kiwi_singleton.py` | 형태소 분석(요청당 1번) |
| `eojeol_bounds(text, i)` | `hangul.py` | i번 글자가 속한 어절의 `[시작,끝)` |
| `final_index(ch)` | `hangul.py` | 받침 번호 |
| `tokens_within(tokens, s, e)` | `morphology.py` | 구간 안의 토큰만 |
| `join_changed(kiwi, morphs, orig)` | `morphology.py` | 고친 형태소를 글자로 조립 |
| `sentence_slices(tokens)` | `morphology.py` | 문장 단위로 자름 |

### 두 가지 고치는 방식

| 방식 | 어떻게 | 어디서 |
|---|---|---|
| **문자열 치환** | `을`→`를` 처럼 정한 글자로 바꿈 | josa, dictionary, yul_ryul |
| **형태소 재조립** | 형태소 목록을 고치고 `kiwi.join`으로 활용형을 되살림 | honorific, tense, negative_polarity, morph_rules … |

재조립은 "포기할 것이다"를 "포기하지 않을 것이다"로 바꿀 때처럼, 활용이 얽힌 자리를 **Kiwi의 결합 규칙에 맡기는** 방법입니다. 활용마다 규칙을 따로 적지 않아도 됩니다.

## 6.1 jamo.py: 흩어진 자모 합치기

**목적:** `ㅂㅐ고프다`처럼 글자가 합쳐지지 않은 것을 `배고프다`로.
**왜:** 입력기(IME)가 조합에 실패해서 `ㅂ`과 `ㅐ`가 따로 남는 일이 있습니다.

### 로직

정규식으로 **"자음 다음에 바로 모음"**인 모양을 찾습니다.

```python
CHO  = "ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ"     # 초성 19개
JUNG = "ㅏㅐㅑㅒㅓㅔㅕㅖㅗㅘㅙㅚㅛㅜㅝㅞㅟㅠㅡㅢㅣ"   # 중성 21개
_PATTERN = re.compile(f"[{CHO}] ?[{JUNG}](?:[{JONG[1:]}](?![{JUNG}]))?")
```

의미: 초성 한 글자 + (공백 있어도 됨) + 중성 한 글자 + (받침 있어도 됨). 합칠 때는 2장의 공식을 거꾸로 씁니다.

```python
def _compose(cho_char, jung_char, jong_char=""):
    cho_idx  = CHO.index(cho_char)
    jung_idx = JUNG.index(jung_char)
    jong_idx = JONG.index(jong_char) if jong_char else 0
    return chr(0xAC00 + (cho_idx * 21 + jung_idx) * 28 + jong_idx)
```

`ㅂ`(초성 7번), `ㅐ`(중성 1번) → `(7*21+1)*28 = 4144` → `0xAC00 + 4144` = `배`.

### 함정 두 개

1. **`ㅋㅋㅋ`, `ㅠㅠ`는 건드리지 않는다.** 자음+자음, 모음+모음이라 "자음 다음 모음" 모양이 아닙니다. 인터넷 웃음 표현을 오류로 잡지 않기 위한 설계입니다.
2. **받침 vs 다음 글자의 초성:** `ㅁㅜㄹㅣ`는 `물`+`ㅣ`이 아니라 `무`+`리`입니다. 받침 후보 뒤에 모음이 오면 받침이 아니라 다음 글자의 초성이므로 `(?![{JUNG}])`로 막습니다.

### 실행 결과

```
'ㅂㅐ고프다'      → ㅂㅐ→['배'][medium]
'ㅋㅋㅋ 웃기다'   → (없음)
'ㅁㅜㄹ을 마셨다' → ㅁㅜㄹ→['물'][medium]
```

신뢰도가 `medium`인 이유: 규칙이 확실하지만 사용자가 일부러 쓴 것일 수 있어서(자모를 쓴 말장난 등) high로는 올리지 않았습니다.

## 6.2 dictionary.py + dict_rules.json: 사전 규칙 474개

**목적:** 틀리게 쓰기 쉬운 표기를 목록으로 잡는다.
**방식:** 정규식 474개를 하나씩 적용합니다.

### 규칙 한 개의 모양 (`app/data/dict_rules.json`)

```json
{"pattern": "(?<=카드로 )결재",
 "replacement": "결제",
 "category": "spelling",
 "confidence": "high",
 "message": "대금을 치르는 것은 '결제(決濟)'입니다. '결재(決裁)'는 상급자가 안건을 승인하는 것입니다."}
```

통계(제가 파일을 읽어 센 값): **474개**, 종류별 맞춤법 318 / 문법 151 / 띄어쓰기 5, 신뢰도별 high 443 / medium 23 / low 8.

### 코드 전체의 골격

```python
for rule in _RULES:
    for m in rule["_compiled"].finditer(text):
        suggestions = [m.expand(rule["replacement"])] if rule["replacement"] else []
        issues.append(RawIssue(start=m.start(), end=m.end(), ...,
                               source="dict_rule", ...))
```

- `finditer`: 글 안에서 패턴이 맞는 자리를 전부 찾습니다.
- `m.expand(replacement)`: 치환 문자열 안의 `\1` 같은 그룹 참조를 채웁니다. 규칙이 "일부는 그대로 두고 일부만 바꾸기"를 할 수 있게 해 줍니다.
- `replacement`가 비어 있으면 제안 없이 지적만 합니다(low 규칙들).

### 핵심 기법: 문맥을 정규식에 넣기

`결재/결제`는 글자만 봐서는 못 가릅니다. 그래서 **앞말을 확인하는 `(?<=...)`**를 씁니다.

```
카드로 결재했다   → 결제   (카드로 → 대금)
서류를 결재했다   → (없음) (서류를 → 승인, 맞음)
```

실제로 돌려 본 결과입니다. 두 번째 문장은 건드리지 않습니다.

### 실제 사고: 정문을 고치던 규칙 9개

README에 기록된 사건입니다. 규칙별로 정문 표본에서 발동한 것을 사람이 읽었더니 **정문을 고치고 있던 규칙이 9개**였습니다. 전체 오탐률 0.0009에는 하나도 안 나타났습니다.

| 규칙 | 무엇을 고치려 들었나 |
|---|---|
| `들께 → 들게` | "거룩한 스님**들께** 귀의합니다" (`들`+`께`: 높임 조사) |
| `희안 → 희한` | 조선 공신 **성희안** (사람 이름) |
| `금새 → 금세` | **황금새**벽당 (`황금`+`새벽`) |
| `역활 → 역할` | **교역활**동 (`교역`+`활동`) |

해결: 단어 경계를 정규식에 넣었습니다(`(?<![가-힣])금새`: "금새 앞에 한글이 오면 안 된다"). 이름처럼 글자로 구분이 안 되는 두 개는 신뢰도를 `low`로 내려 자동 적용을 껐습니다.

### 작은 발견

`금새`를 실행해 보니 같은 자리가 **두 번** 나옵니다(`dict_rule` 2건). `dict_rules.json`에 같은 규칙이 두 줄 들어 있기 때문입니다. 병합(5장)이 겹치는 것을 하나로 줄여 주므로 사용자에게는 영향이 없지만, 파일 정리 후보입니다.

### 같은 파일 안의 `에요/예요`

`받침 없는 말 + 에요 → 예요`는 받침을 계산해야 해서 정규식 사전에 못 적습니다. 코드(`_eyo_issues`)에서 따로 처리합니다. 예외도 코드에 있습니다.

- `이에요`(받침 있는 말 뒤), `아니에요`는 정문
- 뒤에 문장부호가 오지 않으면 고치지 않음 (위키 실측 62건 중 인명·지명 3건이 문장부호 없이 이어졌음)

## 6.3 yul_ryul.py: 율/률

**규칙:** 앞 글자가 모음이거나 ㄴ 받침이면 `율`, 그 밖의 받침이면 `률`.

```python
def _expected(prev_char):
    idx = final_index(prev_char)
    if idx is None: return None
    return "율" if idx in (NO_BATCHIM_INDEX, NIEUN_INDEX) else "률"
```

### 두 관문

| 관문 | 어떤 경우 | 방법 |
|---|---|---|
| 1 | 단어 끝 `성공율`, `실패률` | Kiwi가 `율/률`을 접미사(XSN)로 읽은 자리만 |
| 2 | 단어 안 `자률신경` | **언어모델 점수**로 판단: 고친 쪽이 Kiwi 점수로 5점 이상 더 자연스러울 때만 |

2번이 필요한 이유: `자률신경`은 단어 중간이라 Kiwi가 접미사로 읽지 않습니다. 그런데 `율리우스`처럼 **원래 `율`로 시작하는 이름**도 중간 위치로 보일 수 있어서 점수 차이로 가립니다. 주석의 실측: `자률신경 -37 vs 자율신경 -21`(고친 쪽이 16점 좋음), `율리우스 -23 vs 률리우스 -32`(바꾸면 9점 나빠짐).

```
'성공율이 높다'      → 율→['률'][high]
'비률이 높다'        → 률→['율'][high]
'자률신경'           → 률→['율'][high]
'율리우스 카이사르'  → (없음)
```

## 6.4 josa.py: 조사 (365줄, 가장 복잡한 규칙 검사기)

2장에서 받침 번호로 조사를 고르는 원리를 봤습니다. 이 파일은 그 위에 **"어디가 조사 자리인가"를 찾는 다섯 경로**가 얹혀 있습니다.

### 왜 다섯 경로인가

Kiwi는 틀린 조사를 조사로 안 읽습니다(3장). 그래서 "조사로 태그된 것"을 찾을 수 없고, 상황마다 다른 길로 조사 자리를 찾아야 합니다.

| 경로 | 상황 | 방법 | 예 |
|---|---|---|---|
| (1) | 명사 바로 뒤 | 명사 토큰이 끝나는 자리의 **다음 글자**를 직접 봄 | `학교을` |
| (2) | 조사/접미사에 겹쳐 붙은 보조사 | 그 단어 끝 글자 기준 | `회사에서은` |
| (3) | 괄호 뒤 | **괄호 앞** 글자를 숙주로 | `몰리에르(Moliere)은` |
| (4) | 닫는 따옴표 뒤 | 따옴표 **안쪽** 마지막 글자를 숙주로 | `《비바리》은` |
| (5) | 조사가 붙어 통째로 명사 하나로 읽힌 어절 | 언어모델 점수 차이 4점 이상일 때만 | `진도은` |

### 핵심 함수들

```python
def _check_particle_at(text, end, host_last_char):
    # 로/으로 먼저 (2글자 앞을 봐야 해서)
    expected = _expected_particle(host_last_char, "로", "으로", rieul_exception=True)
    ...
    for no_batchim, has_batchim in [("가","이"), ("를","을"), ("는","은"), ("와","과")]:
        expected = _expected_particle(host_last_char, no_batchim, has_batchim)
        actual = text[end:end+1]
        if actual in (no_batchim, has_batchim) and actual != expected \
           and _particle_boundary_ok(text, end+1, actual):
            return _issue(...)
```

읽기: 숙주 마지막 글자의 받침으로 "기대하는 조사"를 계산하고, 실제 글자가 그 쌍 중 하나인데 기대와 다르면 오류입니다.

### `_particle_boundary_ok`: 조사 뒤는 경계여야 한다

`가수이다`의 `이`: 바로 앞 `수`는 받침이 없으니 "가"여야 한다고 오판할 수 있습니다. 그러나 `이` 뒤에 `다`가 이어집니다. **진짜 조사 뒤에는 공백·문장부호·끝**이 와야 하므로 한글이 바로 오면 조사가 아니라고 봅니다.
예외: `로/으로` 뒤에 `서/써`가 오는 것(`로서`, `로써`)은 허용.

### `_ending_tail_positions`: `뭔가`, `건가`는 조사가 아니다

`뭔가`는 `뭐`+`ᆫ가`(어미)입니다. 받침 ㄴ 뒤에 `가`가 오므로 "받침이 있으니 `이`여야 한다"고 오판합니다. 실측: 구어 정문 3,000문장에서 나온 high 오탐 25건 중 17건이 이 부류였습니다.

가르는 법이 흥미롭습니다. 태그만으로는 못 가릅니다(진짜 오류 `학생가`도 `가/VV + 어/EC`로 읽혀 EC가 걸림). 대신 **어미의 형태**를 봅니다.

```
뭔가   → 어미 형태 'ᆫ가'  첫 글자가 종성 자모(U+11AB) → 앞 음절에 융합 → 조사 아님
학생가 → 어미 '어'        완성형 음절 → 그냥 붙은 조사 자리
```

`fused = "ᆨ" <= head <= "ᇿ" or "ㄱ" <= head <= "ㆎ"`가 그 판정입니다: "첫 글자가 종성 자모 범위인가".

### 실행 결과

```
'학교을 갔다'                    → 을→['를'][high]
'사과이 맛있다'                  → 이→['가'][high]
'서울으로 갔다'                  → 으로→['로'][high]     ← ㄹ 받침 예외
'물로 씻다'                      → (없음)                ← 맞게 쓴 문장
'가수이다'                       → (없음)                ← 경계 가드
'몰리에르(Moliere)은 작가다'     → 은→['는'][high]       ← 괄호 앞 글자 '르' 기준
'《비바리》은 영화다'            → 은→['는'][high]       ← 따옴표 안 '리' 기준
'진도은 갔다'                    → 은→['는'][high]       ← 경로 (5)
'3를 샀다'                       → (없음)                ← 숫자는 판단 보류
```

### 경로 (5)의 안전장치

글자만 보고 고치면 위험합니다: `활동가`, `여행가`는 조사가 붙은 꼴과 글자가 같은 **진짜 단어**입니다. 그래서 "고친 쪽이 Kiwi 언어모델에서 4점 이상 더 그럴듯"할 때만 고칩니다. 실측 여유: 진짜 오류 4.8~11.7, 진짜 단어 1.3.
또 `은/는`, `을/를` 네 개로만 한정합니다. 넓히면 외국 이름이 오탐합니다(`도자이 선 → 도자가`).

## 6.5 dependent_noun.py: 의존명사 띄어쓰기

**규칙(맞춤법 제42항):** 의존명사는 띄어 씁니다. `먹을것` → `먹을 것`.
**의존명사:** 혼자서는 쓰이지 못하고 꾸미는 말 뒤에서만 쓰이는 명사(것, 수, 뿐, 데, 줄, …).

### 기본 로직

```python
if tok.tag != "NNB" or tok.form not in DEPENDENT_NOUNS: continue   # 의존명사 목록
prev = tokens[i-1]
after_determiner = (prev.tag == "MM" and tok.form in {"것","거"} and prev.form not in {"이","그","저",...})
if prev.tag != "ETM" and not after_determiner: continue            # 관형사형 어미 뒤만
if tok.start != prev.start + prev.len: continue                    # 이미 띄어 있음
```

"앞이 관형사형 어미(ETM)일 때만" 확정합니다. 이 한 줄이 `먹을 것`의 `을`(ETM) 뒤 `것`(NNB)을 잡습니다.

### 단어별 가드 (사연이 하나씩 있다)

| 단어 | 가드 | 이유(코드 주석 근거) |
|---|---|---|
| 리 | `-ㄹ 리 없다/있다` 틀일 때만 | `갈릴리`를 `갈리+ㄹ+리`로 읽는 오분석 |
| 지 | 시간 경과 틀(`떠난 지 3년`)일 때만 | `필요한 것이 없는지`의 `지`는 어미 |
| 데 | 뒤에 조사가 붙거나 지배 용언이 올 때만, 쉼표 바로 뒤면 제외 | `활동하는데 실내와…`의 `데`는 연결어미 |
| 뿐 | 뒤에 `더러`가 오면 제외 | `-ㄹ뿐더러`는 연결어미 |
| 걸 | 문장 끝이거나 `그렇다/그러다`가 뒤따르면 제외 | `공부할걸 그랬다`의 `-ㄹ걸`은 종결어미 |
| 이것·그것 | `이/그/저` + `것`이면 제외 | 대명사 한 단어 |
| 차 | 아예 목록에서 제외 | 목적(`연구차`)과 기회(`갔던 차에`)가 규칙이 달라 태그로 못 가름 |

### 실행 결과

```
'먹을것이 없다'          → 것→[' 것'][high]
'할수 있다'              → 수→[' 수'][high]
'이것을 먹어라'          → (없음)        ← 대명사
'갈릴리에서'             → (없음)        ← 틀 용언 없음
'떠난지 사흘'            → (없음)        ← 틀의 단위 목록에 '사흘'이 없음
'떠난지 3년이 지났다'    → 지→[' 지'][high]
'없는데, 괜찮다'         → (없음)        ← 쉼표
'공부할걸 그랬다'        → (없음)        ← -ㄹ걸 어미
'이런걸 봤다'            → 걸→[' 걸'][high]   ← 구어 '걸'(= 것을)
```

`떠난지 사흘`을 못 잡는 것은 한계입니다. `_JI_FRAME_NOUNS`에 `사흘`이 없기 때문입니다. "정문을 건드리느니 놓친다"는 선택의 결과입니다.

## 6.6 particle_spacing.py: 조사는 앞말에 붙인다

**규칙:** 조사는 앞말에 붙여 씁니다. `2006년 부터` → `2006년부터`.

**핵심:** Kiwi가 떨어져 있어도 `부터`를 조사(`J*` 태그)로 읽어 줍니다. 그래서 **태그가 곧 판정**입니다.
`밖에`는 이 방법이 `하나 밖에 없다`(조사 `밖에`, 붙여야 함)와 `문 밖에 서 있다`(명사 `밖` + `에`, 띄는 게 맞음)를 가려 줍니다.

```
'하나 밖에 없다'    →  밖에→['밖에'][high]    (original 에 앞의 공백이 포함됨)
'문 밖에 서 있다'   → (없음)
```

### 목록은 "동음이의가 없는 조사"만

`밖에, 커녕, 부터, 까지, 처럼, 한테, 에게, 께서, 마다, 조차, 마저, 치고, 더러, 보고서` 등.
**일부러 뺀 것:** `보다`(동사 `보다`·부사도 됨), `만`(`삼십 만`의 단위), `로`. 분석이 한 번 틀리면 서로 다른 두 낱말을 붙여 버리기 때문입니다.

### 한 가지 가드: 격조사끼리는 겹치지 않는다

`에게 해`는 바다 이름(에게해)이라 `에게`가 조사로 읽혀도 붙이면 안 됩니다. "격조사 바로 뒤에 격조사가 오는 모양이면 조사로 읽은 분석이 틀린 것"이라는 문법 사실로 막습니다.

## 6.7 quotation.py: 간접 인용 `-라고` 겹침

`온다라고 말했다` → `온다고 말했다`. 종결어미 `-다` 뒤에 `-라고`를 또 붙인 겹침입니다.

```python
if tok.form != "라고" or tok.tag != "JKQ": continue      # 인용 조사
prev = tokens[i-1]
if prev.tag != "EF": continue                            # 앞이 종결어미
if prev.start + prev.len != tok.start: continue          # 사이에 아무것도 없음
```

**직접 인용과의 구분:** `"온다"라고`는 사이에 닫는 따옴표가 있어서 `prev.start + prev.len != tok.start`가 되고 건너뜁니다.

```
'그는 온다라고 말했다'       → 라고→['고'][high]
'그는 "온다"라고 말했다'     → (없음)
'그가 온다고 말했다'         → (없음)
```

## 6.8 question_mark.py: 물음표

1. 문장 끝 어미가 의문 어미(`냐, 니, 나, 야, 가, 까, 느냐`) 중 하나이고,
2. **같은 문장 안에 의문사**(`어디, 누구, 몇, 왜, 언제, 어떻게, …`)가 있다(조사가 아닌 것만).

```
'지금 몇 시야.'      → .→['?'][high]
'어디까지 왔니.'     → .→['?'][high]
'나야.'              → (없음)      ← 의문사 없음
```

## 6.9 honorific.py: 사물 존대

`커피 나오셨습니다` → `나왔습니다`. 높임 `-시-`는 사람에게만 씁니다.

### 어려운 점

"주어가 사람인가 사물인가"는 어느 품사 태그에도 없습니다. 그래서 **명시적 단어 목록**(`data/animacy.json`의 `things`, `inanimate`)에 있는 명사일 때만 발동합니다. 목록에 없는 명사는 침묵합니다(허용 목록 방식).

### 로직

1. 토큰이 `시/EP`이거나 종결어미 `세요/으세요`이면 후보.
2. `_honorified_thing`: 가까운 주어(주격 조사가 붙은 명사, 또는 조사 없이 용언 앞에 놓인 명사)를 찾아 그것이 사물 목록에 있는지 확인.
3. 고칠 말은 **그 어절만** 형태소 재조립: `시`를 빼거나, `세요`를 `습니다`로 바꿈.

### 함정들(코드에 모두 적혀 있음)

| 상황 | 처리 |
|---|---|
| `-어 주세요`, `-지 마세요` | 사람에게 부탁하는 말이라 높임이 맞다 → 건너뜀 |
| `-ㄹ게요` 안의 `시` (`기다리실게요`) | 부탁 형태 `-어 주세요`로 바꿈 |
| `계시다` (말씀이 계시다) | `시` 형태소가 없는 특수 높임말이라 따로: `있으시다`로 |
| `주문하신 커피` | `주문`이 주어가 아니라 파생 동사의 일부라서 → 건드리지 않음 |
| `사장님 말씀이 계시겠습니다` | `님`이 앞에 있어도 가까운 주어(`말씀`)가 대상 |

```
'커피 나오셨습니다'         → 나오셨습니다→['나왔습니다'][high]
'주문하신 커피 나왔습니다'  → (없음)     ← 정문의 높임은 살린다
'사장님이 오셨습니다'       → (없음)     ← 사람
'품절이세요'                → 품절이세요→['품절입니다'][high]
```

## 6.10 animacy_particle.py: 에게 / 에

유정물(사람·동물)에는 `에게`, 무정물에는 `에`를 씁니다. `동생에 선물을 주었다` → `동생에게`.

**한계가 곧 설계:** Kiwi는 유정/무정을 모릅니다. 네 문장 모두 `NNG + JKB`로 똑같이 분석합니다. 그래서 명사 목록(`animate`, `inanimate`)을 씁니다.

### 비대칭 설계

| 방향 | 조건 |
|---|---|
| `에게` → `에` (무정물 명사 뒤의 `에게`) | 명사가 목록에 있으면 **바로** |
| `에` → `에게` (유정물 명사 뒤의 `에`) | 명사가 목록에 있고 **그 문장에 수여 동사(주다 등)가 있을 때만** |

두 번째가 더 까다로운 이유: `에`에는 여격 말고도 장소(`학교에 갔다`), `~에 대하여` 등 의미가 많습니다. 주석: "나머지를 하나하나 제외하는 건 끝이 없다(`에 대하여`, `에 준하여`, `에 선정되다`, `에 미치다` …). **교정 쪽을 허가제로 바꿨다.**"

```
'동생에 선물을 주었다'     → 에→['에게'][high]
'꽃에게 물을 주었다'       → 에게→['에'][high]
'고양이에 사료를 줬다'     → 에→['에게'][high]
'학교에 갔다'              → (없음)
```

## 6.11 negative_polarity.py: 부정 호응

`결코, 전혀, 좀처럼, 도저히, 도무지, 여간, 차마, 그다지, 미처`는 부정과 함께 쓰입니다.
`그는 결코 포기할 것이다` → `포기하지 않을 것이다`.

### 로직 순서

1. 이 부사(MAG)를 찾는다.
2. 문장 끝까지의 구간에 부정 표지(`않, 못, 안, 없, 아니, 말…` 또는 `…없다`로 끝나는 말)가 있으면 정문 → 끝.
3. 허용되는 서술어(`전혀 다르다`, `전혀 새롭다` 등)가 있으면 정문 → 끝.
4. `미처 -기 전에` 틀이면 정문 → 끝.
5. 부사가 지배하는 **첫 서술어**를 찾는다(3어절 이내).
6. 고치기: `-ㄹ 수 있다`는 `있다`→`없다`, 나머지는 서술어 뒤에 `-지 않-`을 붙인다.

```
'그는 결코 포기할 것이다'         → 포기할→['포기하지 않을'][high]
'도저히 이해할 수 있다'           → 있다→['없다'][high]       ← 수 있다는 없다로
'전혀 다르다'                     → (없음)                   ← 허용 서술어
'그는 결코 포기하지 않았다'       → (없음)
```

### 코드에 남은 사연

`_clause_end`의 주석: Kiwi는 문장 중간에서도 `좋진`을 `좋/VA + 지/EF + ᆫ/JX`처럼 EF(종결어미)로 읽을 때가 있습니다. 그 EF를 문장 끝으로 믿으면 **뒤에 이어지는 부정을 못 보고** 멀쩡한 문장을 부정 없다고 오판합니다.
그래서 "EF 뒤에 문장 끝 부호가 따라올 때(또는 글의 끝일 때)만 진짜 문장 끝"으로 바꿨습니다. (git 기록에도 `fix: stop the polarity rule from reversing three readings` 커밋이 있습니다. 이 주석과 같은 수정인지는 제가 diff를 확인하지 않았습니다.)

## 6.12 tense.py: 시제 호응

`어제 친구를 만난다` → `만났다`. 시간 부사와 서술어의 시제가 정면으로 어긋날 때만 잡습니다.

### 모델: 시간 표지 × 서술어 시제

| 시간 표지 | 값 | 예 |
|---|---|---|
| 과거 부사 | PAST | 어제, 그저께, 방금, 아까, 예전 |
| 과거 명사 | PAST | 작년, 지난주, 지난달 |
| 미래 | FUTURE | 내일, 모레, 내년, 이따가, 다음 주 |
| `N 전` | PAST 또는 **DATED_PAST** | 조금 전 / 9만 년 전 |

| 서술어 시제 | 판정 |
|---|---|
| `었/았/였` | PAST |
| `겠`, `-ㄹ 것이다` | FUTURE |
| 그 외 용언 | PRESENT |

**모순이 되는 쌍만** 지적합니다.

```python
_CONTRADICTIONS = {(PAST, PRESENT), (PAST, FUTURE), (DATED_PAST, FUTURE), (FUTURE, PAST)}
```

`DATED_PAST`(오래된 시점)는 `PRESENT`와 모순이 아닙니다. 백과사전식 글에서 "9만 년 전에 출현한다"처럼 역사적 현재를 쓰기 때문입니다. 코드 주석의 측정 근거입니다.

### 함정

- **관형절 안의 부사**는 주절 서술어와 무관합니다(`5만 년 전에 시작되는 시대로 연결된다`). 그래서 ETM을 절 경계로 봅니다.
- `다음 주`는 이미 이야기한 시점을 기준으로도 쓰입니다(`그 다음주까지 머물렀다`). `그/이/저` 관형사가 앞에 있거나 `도`가 뒤따르면 판단 안 함.
- `이다`(VCP)는 사건이 없어서 제외(`몇 년 전 SBS인가?` 오탐).

```
'어제 친구를 만난다'    → 만난다→['만났다'][high]
'내일 회의가 열렸다'    → 열렸다→['열린다'][high]
'어제 친구를 만났다'    → (없음)
```

## 6.13 redundant_causative.py: 불필요한 `-시키다`

`사원을 교육시키다` → `교육하다`. 이미 목적어를 취하는 `-하다`에는 `-시키다`가 군더더기입니다.

**어려운 점:** `향상시키다`, `변화시키다`, `입학시키다`는 `-하다`가 자동사라 `-시키다`가 필요합니다(`물을 얼음으로 변화시키다`). 태그로는 못 가릅니다. 그래서 **"이미 타동사인 명사 목록"**(교육, 금지, 실현, 주차, 소개, 설득, …)만 씁니다.

```
'사원을 교육시키다'   → 교육시키다→['교육하다'][high]
'물을 변화시키다'     → (없음)
```

## 6.14 subject_predicate.py: 주술 호응

`내 꿈은 의사가 되고 싶다` → `되는 것이다`. 주어가 추상명사(꿈, 목표, 계획, …)인데 서술어가 사람의 바람(`-고 싶다`)이나 의무(`-어야 하다`)면 주어가 중간에 바뀐 것입니다.

```
'내 꿈은 의사가 되고 싶다'  → 되고 싶다→['되는 것이다'][high]
'꿈은 크다'                 → (없음)
```

`꿈은 크다`는 꿈 자신에 대한 서술이라 건드리지 않습니다. 사람의 태도(`-고 싶다`, `-어야 하다`)만 근거로 삼습니다.

## 6.15 morph_rules.py: 형태소 배열 보기

문자열 규칙은 활용형을 하나씩 적어야 합니다. 이중피동 규칙 7개가 모두 `~지` 한 형태뿐이어서 `잊혀졌다`, `보여집니다`, `닫혀진`을 전부 놓쳤습니다(2026-09-14 탐침 11/11 미탐).
그래서 **"틀린 형태"가 아니라 "틀린 형태소 배열"**을 봅니다.

```
잊혀졌다 → 잊히/VV + 어/EC + 지/VX + 었/EP + 다/EF
              (피동사 어간) (-어)   (-지다)   ← 이미 피동인데 또 -어지다 = 이중 피동
```

고치는 법: 어간은 그대로 두고 `-어지다`를 빼고 나머지 어미를 `kiwi.join`으로 다시 이어 붙입니다 → `잊혔다`.

### 6개 규칙

| 규칙 | 예 | 방식 |
|---|---|---|
| double_passive | 잊혀졌다 → 잊혔다 | 피동사 어간 목록 + `-어지` |
| ha_contraction | 섭섭치 → 섭섭지 | 안울림 받침 뒤 `하` 통째 탈락(제40항 붙임2) |
| nonstandard_stem | 치루었다 → 치렀다 | 비표준 어간 → 표준 어간 |
| rieul_eun | 거칠은 → 거친 | ㄹ 받침 + `은` → `ㄴ` |
| nonstandard_ending | 올런지 → 올는지 | 비표준 어미 표 |
| copula_past | 대작이였다 → 대작이었다 | `이`+`였` 겹침 |

```
'잊혀졌다'     → 잊혀졌다→['잊혔다'][high]
'섭섭치 않다'  → 치→['지'][high]
'치루었다'     → 치루었다→['치렀다'][high]
'거칠은 손'    → 거칠은→['거친'][high]
'대작이였다'   → 이였→['이었'][high]
'올런지 모르겠다' → 올런지→['올는지'][high]
```

### 주목할 설계 판단

- **이중피동 어간은 어휘로 제한합니다.** `-히/이/기/리`로 끝난다는 이유만으로 넣으면 안 됩니다. `밝히다`+`-어지다`(밝혀지다)는 정문이기 때문입니다.
- **`개이다→개다` 규칙은 뺐습니다.** 구어 실측 `정상은 개였다`(`개`+`이었다`)를 날씨 `개다`로 읽었기 때문입니다. "형태만으로는 못 가른다"고 판단했습니다.
- **`ha_contraction`은 단어가 거기서 끝나야 합니다.** `접착치과학`(접착+치과학)을 `접착하+지`로 읽는 오탐이 위키 1건 있었습니다.

## 6.16 consistency.py: 문체 일관성 (유일하게 글 전체를 보는 검사기)

한 글 안에서 `-습니다`와 `-한다`가 섞였는지 봅니다. **틀린 것이 아니라 통일되지 않은 것**이라서 문장 하나만 보면 전부 정문입니다.

### 알고리즘 (다수결)

```
1. 문장 단위로 쪼개고, 문장마다 마지막 종결어미(EF)로 문체를 분류
     합쇼체: 습니다, ᆸ니다, 십시오 …    해요체: 어요, 아요, 세요, 죠 …    해라체: 다, ᆫ다, 었다 …
2. 관용 인사(안녕하세요, 감사합니다 …)는 문체 표지가 아니라서 제외
3. 문체가 2종류 이상이고 다수 문체가 60% 이상이면
4. 소수 문체 문장을 다수 문체로 바꾸자고 제안한다
5. 단, 합쇼체↔해요체는 존댓말 안의 폭이므로 지적만 하고 고쳐 쓰지는 않는다
```

2문장이 1:1이면 다수결이 안 되므로 **첫 문장이 문체를 정한다**는 관례를 쓰되 `low`로 둡니다.

```
'보고서를 제출했습니다. 검토 부탁한다. 확인해 주십시오. 감사합니다.'
  → 부탁한다→['부탁합니다'][medium]
```

(합쇼체 3, 해라체 1이므로 다수는 합쇼체. `감사합니다`는 관용 인사라 표지 제외.)

### 실제 사고

줄을 손으로 끊어 쓴 글에서 `알려줍니\n다.`처럼 **단어 가운데 줄바꿈**이 있으면 Kiwi가 `알려줍니/NNG + 이/VCP + 다/EF`로 읽습니다. 그대로 문체를 바꾸면 `알려줍니입니다` 같은 **없는 말**이 만들어졌습니다(2026-09-17 실측). 그래서 줄바꿈이 낀 구간은 **제안을 만들지 않고** 지적만 남깁니다.

## 6.17 이 장에서 가져갈 것

1. 규칙은 **발동 조건 몇 줄 + 예외 수십 줄**로 이루어진다. 예외 하나하나가 실제 오탐 사건이다.
2. 안전을 위해 **"허용 목록"**을 쓴다: 목록에 있는 것만 고치고 나머지는 침묵.
3. 확신이 부족하면 **신뢰도를 low로 내려** 자동 적용만 끈다(탐지는 남긴다).
4. 활용이 얽힌 고침은 **형태소를 고치고 `kiwi.join`으로 다시 조립**한다.
5. Kiwi의 분석 한 번이 틀리면 그 위의 규칙이 틀린다. 그래서 가드는 대개 **"Kiwi가 틀리게 읽는 알려진 모양"**을 막는 것이다.
