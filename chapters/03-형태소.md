# 3장. 형태소 분석: 문장을 조각내고 이름표 붙이기

## 3.1 왜 필요한가

`학교를`과 `학교에서`와 `학교는`은 글자로는 다른 단어처럼 보이지만 모두 `학교` + 조사입니다.
교정기가 "조사 `을`이 맞는가"를 보려면 먼저 **어디까지가 명사이고 어디부터가 조사인지** 알아야 합니다.
이것을 해 주는 프로그램이 **형태소 분석기**이고, 다듬이 쓰는 것은 **Kiwi**(kiwipiepy 0.23.2, LGPL-3.0)입니다.

> 중요: Kiwi는 다듬이 만든 것이 아닙니다. 다듬의 규칙 검사기 대부분이 Kiwi의 분석 결과 위에서 돌아갑니다.
> Kiwi가 틀리게 읽으면 그 검사기도 틀립니다. 이 장 뒤쪽이 "Kiwi를 믿을 때와 못 믿을 때"입니다.

## 3.2 용어

| 용어 | 뜻 | 예 |
|---|---|---|
| **어절** | 공백으로 나뉜 덩어리 | `학교를` |
| **형태소** | 뜻이나 문법 기능이 있는 가장 작은 조각 | `학교` / `를` |
| **품사 태그** | 형태소의 종류 이름표 | `NNG`, `JKO` |
| **어간** | 활용하는 말의 변하지 않는 부분 | `먹`(먹다) |
| **어미** | 어간 뒤에 붙어 문법 기능을 하는 조각 | `었`, `다`, `던` |
| **토큰** | 분석기가 돌려주는 조각 한 개 (형태소 하나에 해당) | |

## 3.3 실제 분석 결과

`kiwi.tokenize(text)`는 토큰의 목록을 돌려줍니다. 토큰 하나에는 `form`(글자), `tag`(품사), `start`(시작 위치), `len`(길이)이 있습니다.
직접 돌려 본 결과입니다.

```
학교를 갔다
  학교 /NNG  start=0 len=2
  를   /JKO  start=2 len=1
  가   /VV   start=4 len=1
  었   /EP   start=4 len=1
  다   /EF   start=5 len=1
```

- `학교/NNG`: 일반명사. `를/JKO`: 목적격 조사.
- `갔다`가 `가/VV` + `었/EP` + `다/EF`로 쪼개졌습니다. `가다`의 `가`(어간) + 과거 `-았/었-`(선어말어미) + 종결어미 `다`.
- 주목: **`가`와 `었`의 start가 둘 다 4**입니다. `갔`이라는 한 글자 안에 두 형태소가 녹아 있기 때문입니다.
  또 과거 어미의 원래 모양은 `았`인데 Kiwi는 `었`으로 정규화해 돌려줍니다. 그래서 **`form`이 원문 글자와 항상 같지는 않습니다.**
  원문과 대조해야 할 때 코드가 `text[pos:pos+1]`로 다시 확인하는 이유입니다(`confusion.py`의 `든` 잠금).

## 3.4 품사 태그표 (다듬 코드에 나오는 것들)

| 태그 | 이름 | 예 |
|---|---|---|
| NNG | 일반명사 | 학교, 친구 |
| NNP | 고유명사 | 손병호, 서울 |
| NNB | 의존명사 | 것, 수 |
| NP | 대명사 | 나, 이것 |
| NR | 수사 | 하나 |
| VV | 동사 | 먹-, 가- |
| VA | 형용사 | 예쁘-, 많- |
| VX | 보조용언 | 있-(먹고 있다) |
| VCP / VCN | 이다 / 아니다 | |
| MAG | 일반부사 | 너무, 매우 |
| MM | 관형사 | 이런, 모든 |
| JKS / JKO / JKB / JKG | 주격 / 목적격 / 부사격 / 관형격 조사 | 가, 를, 에, 의 |
| JX / JC | 보조사 / 접속조사 | 은/는, 와/과 |
| EP | 선어말어미 | 었, 시 |
| EF | 종결어미 | 다, 요 |
| EC | 연결어미 | 고, 는데, 든 |
| ETM | 관형사형 전성어미 | 는, 던, ㄴ |
| ETN | 명사형 전성어미 | 음, 기 |
| XSN / XSV / XSA | 명사 / 동사 / 형용사 파생 접미사 | -적, -하, -스럽 |
| SF | 문장 끝 부호 | . ? ! |
| SN / SL / SH | 숫자 / 외국어 / 한자 | |

**`-I`, `-R`이 붙은 태그**(`VA-I`, `VV-R`)는 불규칙 활용 표시입니다. 다듬은 `pos_base(tag)`로 `-` 뒤를 떼어 씁니다.

```python
def pos_base(tag):
    return tag.split("-")[0]     # 'VV-R' -> 'VV'
```

## 3.5 같은 글자, 다른 분석: 다듬이 품사를 보는 이유

글자만 봐서는 구분할 수 없고 품사를 봐야 답이 갈리는 경우가 이 프로젝트에 많습니다.
같은 `든`인데 Kiwi가 읽는 방식에 따라 이렇게 갈립니다.

```
봤든 사람   → 보/VV  었/EP  든/ETM  사람/NNG     든이 '관형사형 어미'(ETM)
먹었던 밥   → 먹/VV  었/EP  던/ETM  밥/NNG
```

`든`을 ETM(명사를 꾸미는 어미)으로 읽은 자리는 문법상 `던`이어야 합니다. `든`은 연결어미(EC)라서 명사를 꾸미지 못하기 때문입니다.
이 한 줄이 `confusion.py`의 `_adnominal_den_spans`입니다. "확률이 아니라 문법으로 확정"하는 예입니다.

## 3.6 Kiwi가 틀린 문장을 어떻게 읽는가

오류가 들어간 문장을 Kiwi는 "모르는 말"로 처리하거나 엉뚱하게 읽습니다. 실제로 이렇습니다.

```
학교을 갔다   → 학교/NNG  을/NNG  가/VV ...
```

**`을`이 조사(JKO)가 아니라 명사(NNG)로** 읽혔습니다. 틀린 조사를 조사로 인정하지 않은 것입니다.
그래서 조사 검사기는 "조사로 태그된 것을 찾는" 방식으로 만들 수 없습니다. 오류가 있는 바로 그 자리가 조사로 태그되지 않으니까요.

> `josa.py` 주석의 뜻(의역): 틀린 조사는 Kiwi가 다른 것으로 다시 태깅하기 때문에(`학교을`의 `을`이 NNG가 된다), 태그만 훑으면 실제 오류를 전부 놓친다.

그래서 방식을 뒤집습니다. **명사 토큰이 끝나는 바로 다음 글자**를 직접 보고, 그 글자가 조사 후보(`을/를/은/는/이/가/와/과/로/으로`)이면서 받침 규칙과 어긋나는지 봅니다.
6장에서 코드로 봅니다.

## 3.7 요청 한 번에 분석은 한 번만: 캐시

검사기가 21개인데 각자 `kiwi.tokenize(text)`를 부르면 같은 문장을 21번 분석합니다. 느립니다.
두 장치가 있습니다.

**① `tokenize_cached` (`app/kiwi_singleton.py`)**

```python
@lru_cache(maxsize=8)
def tokenize_cached(analyzer, text):
    return analyzer.tokenize(text)
```

`@lru_cache`는 "같은 입력이 오면 계산 없이 저번 결과를 돌려주라"는 표시입니다(최근 8개 기억).
주의 문구가 달려 있습니다: **"반환된 목록은 공유되므로 읽기 전용으로 쓸 것."** 한 검사기가 목록을 고치면 다른 검사기가 오염됩니다.

**② `_SharedAnalysis` (`app/engine.py`)**

요청 하나 동안만 `tokenize` 결과를 나눠 쓰는 얇은 포장입니다. 검사기들은 `kiwi.tokenize(text)`를 평소처럼 부르는데, 포장이 중간에서 캐시를 끼워 줍니다.
요청마다 새로 만들어서 요청 사이에 메모리가 쌓이지 않습니다.

## 3.8 Kiwi 준비 운동

```python
kiwi = Kiwi(load_default_dict=True, load_typo_dict=False, load_multi_dict=False)
kiwi.tokenize("다듬")      # 서버가 뜰 때 한 번 돌려 둔다
```

- Kiwi의 사전을 어디까지 적재할지는 **메모리와 정확도의 교환**입니다. 파일 안 주석에 실측표가 있습니다.

| 설정 | 메모리 | 부팅 | FPR(오탐률) |
|---|---|---|---|
| 사전 전부 | 578MB | 0.94초 | .0009 |
| 다중어 사전 끔 (현재) | 429MB | 0.46초 | .0009 |
| 기본 사전도 끔 | 344MB | 0.33초 | .0014 |

다중어 사전을 끄면 정밀도·오탐률이 소수 넷째 자리까지 같고 메모리가 149MB 줄어서 껐습니다.
기본 사전은 켜 둡니다. 껐을 때 오탐률이 .0009 → .0013으로 오르는데, 이 엔진이 가장 신경 쓰는 게 오탐이라 "조용히 맞바꾸지 않는다"는 판단입니다.

- 마지막 줄 `kiwi.tokenize("다듬")`은 **미리 한 번 돌려서** 내부 구조를 만들어 두는 것입니다.
  안 하면 첫 사용자가 120MB 할당과 약 300ms 지연을 떠안습니다.
