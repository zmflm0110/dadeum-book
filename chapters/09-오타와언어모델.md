## 9.1 어절 사전 (`app/lexicon.py`): 181만 개의 "아는 말" 목록

### 무엇인가

한국어 위키백과에서 **어절이 몇 번 쓰였는지** 센 표입니다.
`count("매일") = 3005`, `count("매읽") = 0`. 사전 크기는 **1,806,050개**입니다.

### 질문 두 개에 답한다

| 질문 | 방법 |
|---|---|
| 이 어절이 말인가? | `count(word) > 0` (`knows`) |
| 얼마나 흔한 말인가? | `count(word)` 값 자체 |

두 번째가 중요합니다. 이름(`발맹`, `모리요`)도 사전에는 몇 번 나옵니다. **오직 횟수만이** "사람이 쓰려던 흔한 말"과 "이름"을 구별합니다.

### 저장 방식: 해시 + 이진 탐색

181만 개 단어를 파이썬 문자열로 들고 있으면 메모리가 너무 큽니다. 그래서 단어 대신 **64비트 지문(해시)**을 저장합니다.

```python
def eojeol_hash(word):
    digest = hashlib.blake2b(word.encode(), digest_size=8).digest()
    return int.from_bytes(digest, "big") - (1 << 63)
```

파일 구조: `[메타 JSON 한 줄] [해시 배열(정렬됨)] [횟수 배열(같은 순서)]`. 단어를 찾을 때는 해시를 계산하고 **이진 탐색**(정렬된 목록에서 가운데를 찍어 앞뒤를 가르는 스무고개)으로 찾습니다.

```python
def count(self, word):
    h = eojeol_hash(word)
    i = bisect_left(self._hashes, h)
    if i < len(self._hashes) and self._hashes[i] == h:
        return self._counts[i]
    return 0
```

### 해시의 위험과 안전한 방향

해시는 서로 다른 단어가 같은 지문을 가질 수 있습니다(충돌). 181만 개에서 확률은 약 천만분의 일입니다.
**충돌이 나면 "모르는 말을 안다고 착각"합니다.** 그러면 오타를 놓치는 쪽(미탐)으로 틀리지, 멀쩡한 말을 고치는 쪽(오탐)으로 틀리지 않습니다. 이 프로젝트는 이 방향을 일부러 택했습니다.

### 왜 `lexicon.bin`을 따로 만들었나

원본 통계 파일(`stats_ko.json`, 60MB)은 용량·라이선스 정책상 저장소에 없습니다(`.gitignore`). 그러면 오타 검사는 CI·도커·새 체크아웃에서 **조용히 꺼집니다.**
그래서 오타 검사에 필요한 부분만(해시 + 횟수) 추려 **21.7MB**로 커밋했습니다(`ml/export_lexicon.py`). 쓰기 전에 무작위 2만 개를 다시 읽어 횟수가 같은지 검증합니다.

## 9.2 키보드 거리 (`app/keystrokes.py`): "손가락이 한 번 헛디딘 것"

### 왜 글자 거리가 아니라 키 거리인가

```
매읽 ↔ 매일    ㄺ(ㄹ+ㄱ)이 ㄹ로: 키 하나를 더 누른 것   → 손 실수
구촌 ↔ 구몬    ㅊ과 ㅁ: 키보드 양 끝                    → 다른 단어
```

글자 단위(음절)로나 자모 단위로 봐도 두 쌍 모두 "한 군데 다름"입니다. 그러나 사람의 손은 `ㅊ`을 누르려다 `ㅁ`을 누르지 않습니다. 그래서 **자판 위치**를 계산합니다.

### 자판 배치 (두벌식)

```python
_ROWS = (
    "ㅂㅈㄷㄱㅅㅛㅕㅑㅐㅔ",     # 윗줄
    "ㅁㄴㅇㄹㅎㅗㅓㅏㅣ",       # 가운뎃줄
    "ㅋㅌㅊㅍㅠㅜㅡ",           # 아랫줄
)
_SHIFTED = {"ㅃ":"ㅂ", "ㅉ":"ㅈ", "ㄸ":"ㄷ", "ㄲ":"ㄱ", "ㅆ":"ㅅ", "ㅒ":"ㅐ", "ㅖ":"ㅔ"}
```

- 각 자모에 `(줄, 칸)` 좌표를 줍니다.
- 쌍자음(`ㅃ` 등)은 같은 키에 Shift를 누른 것이라 같은 위치로 봅니다(Shift를 놓친 것은 실수).
- **이웃**: 줄 차이 ≤ 1 이고 칸 차이 ≤ 1.

### 글자를 키 입력열로 풀기

```python
def keystrokes(word):
    for ch in word:
        initial, vowel, final = decompose(ch)         # 2장의 공식을 거꾸로
        out.append(INITIALS[initial])
        out.extend(_COMPOUND_VOWEL.get(VOWELS[vowel], VOWELS[vowel]))
        if final: out.extend(_COMPOUND_FINAL.get(FINALS[final], FINALS[final]))
```

겹받침·겹모음은 **두 번 누르는 키**로 풀립니다(`ㄺ` → `ㄹ`,`ㄱ`).

```
매읽  → ㅁ ㅐ ㅇ ㅣ ㄹ ㄱ   (6키)
매일  → ㅁ ㅐ ㅇ ㅣ ㄹ      (5키)
```

### 한 번의 실수 판정: `one_slip`

```python
def one_slip(typed, intended):
    a, b = keystrokes(typed), keystrokes(intended)
    if abs(len(a) - len(b)) > 1: return False           # 키 수가 2개 이상 다르면 아님
    if len(a) == len(b):                                  # 같은 길이: 한 키만 달라야, 그것도 이웃 키
        differing = [(x, y) for x, y in zip(a, b) if x != y]
        return len(differing) == 1 and adjacent(*differing[0])
    # 길이가 1 다름: 한 키를 더 눌렀거나 빼먹은 것
    shorter, longer = (a, b) if len(a) < len(b) else (b, a)
    return any(longer[:i] + longer[i+1:] == shorter for i in range(len(longer)))
```

세 가지 실수만 인정: **한 키를 더 누름 / 빼먹음 / 이웃 키를 누름**.

### 후보 만들기: `near_misses`

단어의 글자 하나에서 초성·중성·종성 중 **하나만** 바꿔 만든 모든 단어입니다(유효한 한글만).
`매읽`에서 만든 후보는 **130개**였고, 그중 `one_slip`을 통과한 것은 **54개**입니다. 54개 중에서 다음 단계(빈도 기준)를 통과한 것이 `매일` 하나였습니다.

## 9.3 오타 검사 (`checkers/typo.py`): 여섯 개의 문

문마다 실측으로 정해진 사연이 있습니다. `매읽 그 영화 봤다.`에서 직접 따라가 봅니다.

| 단계 | 문 | `매읽`의 결과 |
|---|---|---|
| 1 | 한글 어절이고 **사전에 없다** | `count("매읽") = 0` ✓ |
| 2 | **Kiwi도 못 읽었다**(머리를 NNG/NNP로 추측만 함, 뒤에는 조사·어미뿐) | `_guessed_head` = (0, 2) ✓ |
| 3 | 머리가 2~3음절 | 2음절 ✓ |
| 4 | **형태소 사전**(gyeol-lm)에서도 모른다 | `_known_morpheme` = False ✓ |
| 5 | **키 한 번 실수**로 닿는 흔한 말(2음절 600회+, 3음절 100회+) | 후보 130 → 54 → `매일`(3005회) ✓ |
| 6 | 후보가 **정확히 하나** 남거나 언어모델이 고름 | 하나 ✓ |

### 문 2의 근거: Kiwi가 읽을 수 있으면 오타가 아니다

`갈래는`은 어절 전체로는 사전에 없지만 `갈래`+`는`으로 분명히 읽힙니다. 그래서 Kiwi가 **"추측했다"**는 흔적(머리가 NNG/NNP 하나이고 뒤에 조사·어미만)이 있을 때만 후보로 삼습니다. 이 문 하나로 정문 오탐이 **18.8% → 3.0%**로 줄었습니다.

### 문 3의 근거: 1음절은 위험하다

한 음절 문자열은 거의 다 단어이고, 아닌 것은 여러 단어에 한 번씩 닿습니다. 긴 어절은 이름·합성어라 사전에 없다는 사실이 아무것도 말해 주지 않습니다. 그래서 2~3음절만 봅니다.

### 문 5의 근거: 이름도 "아는 말"이다

`발맹`, `모리요`, `허준로`도 몇 번씩 나옵니다. 오직 횟수만이 "사람이 쓰려던 말"과 "이름"을 가릅니다.
2음절은 더 많은 이웃과 충돌하기 쉬워 **600회**, 3음절은 **100회**를 기준으로 합니다. 코드 주석의 측정: 3음절을 2음절 기준(600)에 맞추면 복원할 수 있는 것의 3분의 1을 잃는데(`완주군` 225회, `모나코`), 정문 점선 밑줄 감소는 0.3%p뿐이었습니다.

## 9.4 이 오타를 "고칠" 것인가 "물어볼" 것인가

여섯 개의 문을 모두 통과해도 대부분은 **low(점선)**로만 냅니다. 왜냐하면:

> 이름은 끝이 없습니다. `딕터`, `라나카`, `하찌`, `항가리`는 모두 사전에 없고 모두 흔한 말에서 한 번 실수한 모양입니다.
> 정문에서 측정하면 0.35%(위키), 0.37%(구어)가 걸리는데 이는 자동 적용 예산의 두 자릿수 배입니다.

그러나 **조건이 모두 맞으면 high로 올립니다** (코드의 `sure`).

```python
_CONFIDENT_GAP = 10.0
sure = gap >= _CONFIDENT_GAP and _is_one_off_common_noun(text, tokens, head_start, head_end, word)
confidence = "high" if sure else "low"
```

| 조건 | 뜻 |
|---|---|
| `gap ≥ 10` | 언어모델이 "고친 쪽이 10점 이상 더 자연스럽다" |
| `_is_one_off_common_noun` | Kiwi가 NNG 하나로 읽었고, **글 안에서 한 번만** 나옴 |

### 한 번만 나와야 하는 이유

코드 주석: 정문에서 high로 오탐한 사례가 모두 세 가지 모양이었고, 모델 없이도 보였습니다.

| 모양 | 예 | 왜 위험 |
|---|---|---|
| 합성어 | `학술직` → Kiwi가 `학술`+`직`으로 읽음 | 모르는 말이 아니라 합성어 |
| 고유명사 추측 | `켐퍼스` → NNP | Kiwi의 추측이 "이름" |
| **같은 글에서 두 번 이상** | `주허` | **오타는 한 번뿐이고, 의도한 이름은 되돌아온다** |

### 실제 결과

```
'매읽 그 영화 봤다.'     → 매읽→['매일'] high   (margin 11.73, 한 번뿐인 NNG)
긴 예문 속 '매읽'        → low                   (margin 8.03 < 10)
'나는 매읽 운동한다.'    → 지적 없음(typo는 침묵, anomaly 점선만)
```

세 번째가 **한계의 실제 사례**입니다. Kiwi가 `매읽`을 `매/NNG + 읽/VV`로 "분석에 성공"해 버려서 문 2(Kiwi가 추측했는가)를 통과하지 못합니다.

## 9.5 언어모델 gyeol-lm (`app/ngram_lm.py`): "어느 쪽이 더 한국어다운가"

### 무엇을 하는 모델인가

두 가지 쓰기 중 어느 쪽이 더 자연스러운 한국어인지 **점수**를 냅니다. 고칠 말을 만들지는 않습니다.
점수가 높을수록 자연스럽습니다.

```
나는 학교에 갔다.    -27.61
나는 학교을 갔다.    -35.50      ← 7.89점 낮음
```

### 어떻게: 세 개씩 묶어 세기 (3-gram)

위키 문장을 형태소로 쪼개서 **연속한 세 형태소가 몇 번 나왔는지** 셉니다.

```
"나는 학교에 갔다."   →   ['<s>', '▁나', '는', '▁학교', '에', '▁가', '▁었', '다', '.']
                          3-gram:  <s> ▁나 는  /  ▁나 는 ▁학교  /  는 ▁학교 에 ...
```

- `<s>`는 문장 시작 표시.
- **`▁`(밑줄 막대)는 어절의 첫 형태소 표시**입니다. 이게 없으면 `영화보고`와 `영화 보고`가 같은 형태소 세 개라서 구별이 안 됩니다.

실제로 확인한 규모: 1-gram 1,222,405개 / 2-gram 1,224,952개 / 3-gram 534,188개, 전체 토큰 143,404,308개. 파일 36MB.

### 점수 계산: 멍청한 백오프(stupid backoff)

"앞의 두 형태소가 이랬을 때 다음이 이것일 확률"을 로그로 합산합니다.

```
P(고 | ▁영화 ▁보) = count(▁영화 ▁보 고) / count(▁영화 ▁보) = 280 / 2034 = 0.1377
log P = −1.983         ← 실제 모델 출력과 일치
```

세 개 조합이 학습 데이터에 없으면 **한 단계씩 낮춰서** 보되, 단계마다 점수에 `log 0.4`(= −0.916)를 깎습니다.

```
P(c | a b) 가 없으면  →  0.4 × P(c | b)
그것도 없으면          →  0.4 × 0.4 × (c의 단독 빈도, +1 보정)
```

실제로 학습에 없는 조합(`▁영화 ▁쀍 고`)의 점수는 −6.45입니다(−1.83은 두 번 깎은 값).

**왜 "멍청한"인가:** 확률이 합이 1이 되도록 정교하게 정규화하지 않기 때문입니다. 이 용도에서는 **두 후보의 순서**만 필요해서 가장 싼 방식으로 충분합니다. 논문 기준값 0.4를 그대로 썼습니다.

### 두 후보 비교: `margin` (`app/rescore.py`)

```python
def margin(text, start, end, replacement, kiwi):
    lo, hi = _window(text, start, end)               # 고친 자리 양옆 20글자(어절 경계로 넓힘)
    before = text[lo:hi]
    after  = text[lo:start] + replacement + text[end:hi]
    return model.score(morphemes(after, kiwi)) - model.score(morphemes(before, kiwi))
```

양수면 "고친 쪽이 더 자연스럽다". 양옆 20글자만 보는 이유: **문서 반대쪽 문장 때문에 값이 달라지면 안 되기 때문**입니다.

### 중요한 제한: 만들지 않고 고르기만

모듈 설명(`rescore.py`)에 이렇게 적혀 있습니다.

> 생성하는 언어모델은 이 엔진이 말하는 범위를 넓히고, 그 모델이 지어낸 오탐은 나머지 엔진이 맞춰 둔 측정 밖에 있게 된다.
> 그래서 이 모델은 **절대 제안하지 않는다.** 검사기가 규칙으로 후보를 만들면, 이 모듈은 순위만 매긴다.
> 지적할 수 있는 것은 줄거나 순서가 바뀔 뿐 **늘지 않는다.**

### 시도했다가 안 된 용도: 띄어쓰기 심판

"`영화보고`가 `영화 보고`보다 낮다"는 신호가 실제로 있습니다(위 예: −21.34 vs −21.02). 그러나 사람이 라벨링한 16개 편집에서 재 보니 띄어야 할 8개(−19.7~+2.0)와 띄우면 안 되는 8개(−17.8~+3.1)의 값이 **완전히 섞였습니다**. 신호(0.46점)가 문장을 다시 분석할 때 생기는 변동에 묻힙니다. 그래서 띄어쓰기 판정은 8장의 경계 모델(판별 학습)이 계속 맡습니다.

### 모델 크기의 판단

학습 코퍼스: 위키 약 450만 문장 + 구어(nsmc) 문장을 8배 반복. 가지치기(횟수가 기준 미만인 조각 삭제): `{1:1, 2:8, 3:20}`. 36MB. 기준을 `{2, 3}`으로 풀면 127MB가 되고 오타 벤치마크가 11.9% → 12.4%로 오를 뿐이라(531문장 중 약 한 문장 반) 90MB를 더 싣지 않았습니다.

### 알아 둘 점

`▁`(어절 첫머리 표시)를 붙이는 조건은 `token.start가 0이거나 앞 글자가 공백`입니다. 그런데 `갔`처럼 한 글자에 두 형태소가 녹아 있으면 둘 다 같은 `start`를 가져서 **둘 다 `▁`이 붙습니다**(위 예: `▁가 ▁었`). 학습과 추론이 같은 함수를 쓰므로 일관되지만, 읽으면 의아해 보이는 부분입니다.

## 9.6 이상탐지 (`app/anomaly.py`): "이 어절은 낯설다"

### 질문

사전에도 없고(`known=False`), 글자가 이어지는 모양도 한국어답지 않은 어절이 있나?
**고칠 말은 만들지 못합니다.** "여기가 수상하다"만 말하며 항상 low(점선)입니다.

### 점수 공식

어절 앞뒤에 시작 `^`, 끝 `$`를 붙이고, 각 글자가 **앞 두 글자 다음에 올 확률**을 구해 `−log P`가 **가장 큰 글자**를 그 어절의 점수로 삼습니다.

```
score(어절) = max_i  −log P( c_i | c_{i−2}, c_{i−1} )
```

### 왜 평균이 아니라 최댓값인가

긴 어절에 이상한 이음매가 딱 한 군데 있으면 평균이 그것을 희석합니다. 코드 주석: 실측에서 평균 기준은 오문이 정문보다 오히려 낮게 나왔고, 최댓값으로 바꾸자 분리가 생겼습니다.

### 확률: 세 종류를 섞기 (선형 보간)

```
P = 0.70 × P(3-gram) + 0.25 × P(2-gram) + 0.05 × P(1-gram)
```

3글자 조합이 신호의 중심이고 1글자 확률은 "0이 되지 않도록" 바닥을 깔아 줍니다. 단일 모델보다 같은 오탐률에서 탐지율이 6.8% → 10.5%로 올랐다고 주석에 있습니다.

### 판정

```python
def detect(self, text, threshold):
    for word in text.split(" "):
        if self.is_known(word): continue          # 사전에 있으면 건너뜀
        score = self.word_score(word)
        if score > threshold: ...                 # THRESHOLD = 11.25
```

### 실제 점수

| 어절 | 사전에 있나 | 점수 | 결과 |
|---|---|---|---|
| 학교를 | ✓ | 2.49 | — |
| 친구가 | ✓ | 2.56 | — |
| 독재자 | ✓ | 4.02 | — |
| ㅋㅋ | ✓ | 0.00 | — |
| 핡교 | ✗ | 7.81 | 임계값 아래, 침묵 |
| **매읽** | ✗ | **12.44** | **점선** |
| **만낫는데** | ✗ | **12.82** | **점선** |
| 쀍쀍 | ✗ | 19.42 | 점선 |

### 임계값 11.25는 누가 정했나

"오탐 예산 0.5%"를 지키는 값으로 평가 게이트(`eval/detect_eval.py`)의 스윕이 정한 **운영값**입니다. 낮추면 탐지율은 오르지만 예산을 넘습니다. 값을 바꾸면 게이트도 다시 재야 합니다.

### 메모리 문제와 해결 (사연)

통계를 파이썬 `dict`로 들면 메모리가 **581MB 늘었습니다**(Kiwi만 380MB → 961MB). 항목이 350만 개이고 각각이 객체를 잡기 때문입니다. 서버 한 워커 예산이 300~500MB인데 그 3배라서 이 층은 **탐지율 4.3% → 23.6%까지 올려 놓고도 서버에 못 붙이고** 있었습니다.

| 조치 | 내용 |
|---|---|
| 어절 사전 | 값이 필요 없으므로 해시 배열 하나로 |
| n-gram | 글자 종류가 약 3천 개뿐이라 `3-gram`도 `V³ < 2⁶³`. **글자 조합을 정수 하나로 인코딩**한 뒤 정렬 배열 + 이진 탐색 |
| JSON 파싱 봉우리 | 상주는 961→278MB로 줄었지만, JSON을 읽는 순간 봉우리가 741MB. 첫 실행 때 배열을 그대로 `.compact` 파일에 붓고 이후엔 그 파일만 읽음(원본의 수정 시각으로 무효화) |

결과: **+54MB, 로드 0.02초**로 붙였습니다.

> 이 파일(`stats_ko.json`, `.compact`)은 저장소에 없습니다. 새로 받은 환경에서는 이 층이 조용히 꺼져 있습니다(`/api/health`에서 확인).
