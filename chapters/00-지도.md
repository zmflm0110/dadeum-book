# 0장. 이 책을 읽는 법과 전체 지도

## 0.1 이 책의 약속

이 책은 **코드를 한 줄도 모르는 사람**이 끝까지 읽으면 다듬(DaDeum)의 코드를 전부 설명할 수 있게 되는 것을 목표로 합니다.
그래서 모든 장이 같은 순서로 진행됩니다.

| 순서 | 묻는 것 | 예 |
|---|---|---|
| 1 | **무엇을** 하는가 (목적) | "받침을 보고 을/를을 고른다" |
| 2 | **왜** 필요한가 (이유) | "이 규칙이 없으면 `학교을`을 못 잡는다" |
| 3 | **어떻게** 하는가 (로직) | 실제 코드와 한 줄씩 풀이 |
| 4 | **어떻게 확인했는가** (근거) | 실제로 돌려 본 결과, 측정 수치 |
| 5 | **무엇이 문제였고 어떻게 풀었는가** (해결) | 실패 사례와 고친 방법 |

코드 인용은 모두 실제 저장소(`zmflm0110/dadeum`, master 6af0ea5)에서 가져왔습니다.
설명에 나오는 실행 결과는 제가 그 코드를 직접 돌려서 얻은 값입니다. 돌려 보지 않은 것은 "읽은 바로는"이라고 적습니다.

> 이 책에서 가장 중요한 습관 하나: **"그렇다더라"로 넘어가지 않고, 입력을 넣고 출력을 보는 것.**
> 다듬 프로젝트 자체가 그 습관으로 만들어졌습니다. (13장에서 그 이야기를 합니다.)

## 0.2 다듬은 무엇인가

한국어 글을 넣으면 **맞춤법·띄어쓰기·조사·문법 오류에 밑줄을 긋고, 고친 말을 제안하는 프로그램**입니다.
웹 페이지, 크롬 확장, 맥 앱 세 가지 모습이 있고, 셋 다 같은 "엔진"을 씁니다.
전부 내 컴퓨터 안에서 돌고 외부 AI를 부르지 않습니다.

한 문장을 넣으면 이렇게 됩니다.

```
입력:  학교을 가는길에 친구를 만낫는데 그렇게 하면 안되요.

출력:  2-3   '을'     → '를'      (조사, 확실)
       25-26 '안'     → '안 '     (띄어쓰기, 확실)
       26-28 '되요'   → '돼요'    (맞춤법, 확실)
       13-17 '만낫는데' → (없음)   (이상한 말, 애매)
```

## 0.3 전체 지도

```
 사용자가 글을 씀
        │
        ▼
┌───────────────────┐   POST /api/check   ┌──────────────────────────┐
│ 화면 (3종)         │ ──────────────────► │ 서버 backend/ (파이썬)     │
│  웹 frontend/      │                     │                          │
│  확장 extension/   │ ◄────────────────── │  ① Kiwi로 형태소 분석     │
│  맥앱 desktop/     │   issues[] (JSON)   │  ② 검사기 21개가 후보 제출 │
└───────────────────┘                     │  ③ 겹치는 후보 정리(병합)  │
        │                                  └──────────────────────────┘
        ▼
  공유 코어 core/ : 밑줄·고치기·무시·되돌리기 상태 관리
```

| 폴더 | 한 줄 설명 | 이 책의 장 |
|---|---|---|
| `backend/app/` | 교정 엔진 본체 | 4–10장 |
| `backend/ml/` | 모델을 학습시키는 코드 | 7–9장 |
| `backend/eval/` | 엔진이 좋은지 재는 도구 | 11장 |
| `backend/tests/` | 자동 테스트 997개 | 11장 |
| `core/` | 화면 세 개가 공유하는 상태기계 | 12장 |
| `frontend/` `extension/` `desktop/` | 화면 | 12장 |
