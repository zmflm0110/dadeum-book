# 7장. 머신러닝 기초와 혼동쌍 모델

6장의 규칙은 "사람이 조건을 적는" 방식이었습니다. 그런데 `되/돼`처럼 **문맥에 따라 답이 갈리는** 자리는 조건을 다 적기 어렵습니다.
이 장은 "예시를 많이 보여 주고 기계가 스스로 판단 기준을 숫자로 익히게 하는" 방식(머신러닝)과, 다듬이 이것을 어떻게 썼는지를 설명합니다.

> 이 장의 핵심 수치는 제가 배포된 모델 파일(`.ddm`)을 직접 읽어서 손으로 계산한 값입니다.
> 손계산 결과가 `predict_proba()`와 소수점 넷째 자리까지 일치했습니다.

## 7.1 규칙 방식과 학습 방식

| | 규칙 방식 | 학습 방식 |
|---|---|---|
| 판단 기준 | 사람이 `if`로 적음 | 예시에서 기계가 숫자로 익힘 |
| 같은 입력 | 늘 같은 출력 | 늘 같은 출력 (학습이 끝난 뒤엔 고정) |
| 장점 | 이유를 설명할 수 있고 예측 가능 | 조건을 일일이 안 적어도 됨 |
| 단점 | 예외가 끝이 없음 | 이유가 숫자 더미라서 설명이 어려움, 데이터가 필요 |

다듬은 **둘을 섞습니다**. 문법으로 답이 정해지는 자리는 규칙이 먼저 확정하고, 규칙이 못 정하는 자리에서만 모델이 발언합니다.

## 7.2 문제를 "둘 중 하나 고르기"로 바꾸기

`되`와 `돼`는 둘 중 하나입니다. 그래서 문제를 이렇게 바꿉니다.

> 이 문장에서 ▒ 자리에 들어가야 할 것은 `되`인가 `돼`인가?

이런 문제를 **이진 분류**라고 합니다. 입력은 "▒ 자리 주변 글자", 출력은 "`돼`일 확률"입니다.

### 슬롯과 마스킹 (`app/slots.py`)

**슬롯**은 "헷갈리는 짝이 나올 수 있는 자리"입니다. 어디가 슬롯인지는 사람이 정규식으로 정합니다.

```python
_AN_SLOT   = re.compile(r"(?:(?<=\s)|^)안|않")     # 안: 어절 첫머리일 때만. 않: 항상
_DOE_SLOT  = re.compile(r"[되돼](?!지)")           # 되/돼, 단 바로 뒤에 '지'가 오면 제외
_ROSEO_SLOT = re.compile(r"로[서써]")
_DEN_SLOT  = re.compile(r"(?<=[가-힣])[던든]")
```

**왜 이렇게 좁히나:**

- `안`은 `안전`, `안내`, `방안` 같은 말 속에 수없이 들어 있습니다. 그래서 어절 **첫머리일 때만** 슬롯으로 봅니다.
- `되지/돼지`는 동물 `돼지`가 코퍼스에 넘쳐서 "`돼` 뒤에 `지`가 온다"는 **정반대 교훈**을 가르칩니다. 그래서 학습과 추론 양쪽에서 아예 뺐습니다. 그 결과 `되지`/`돼지` 혼동은 교정하지 않습니다.

슬롯 주변 글자를 **양옆 12글자씩** 잘라 오고, 슬롯 자리는 `▒`로 가립니다.

```python
WINDOW = 12
MARKER = "▒"

def make_feature(text, start, end):
    left  = text[max(0, start - WINDOW) : start]
    right = text[end : end + WINDOW]
    return f"{left}{MARKER}{right}"
```

```
"그렇게 하면 안 돼요."   →   "그렇게 하면 안 ▒요."
```

**왜 가리나:** 가리지 않으면 모델이 정답 글자 `돼`를 그대로 읽고 "정답은 돼"라고 외우기만 합니다. 가리면 "주변 문맥만으로 판단"하도록 강제됩니다.

실제로 확인한 성질이 있습니다. **`안 돼요`와 `안 되요`는 가린 뒤 똑같은 문자열**(`그렇게 하면 안 ▒요.`)이 됩니다. 그래서 모델의 답도 똑같습니다(둘 다 P(돼)=0.905). 모델은 "쓰인 글자"를 모르고 "문맥"만 보기 때문에, 문맥에 맞는 답은 하나고 쓰인 글자가 그와 다르면 오류라는 구조입니다.

## 7.3 학습 데이터: 정답이 공짜로 생기는 방법

학습에는 "문제와 정답" 쌍이 많이 필요합니다. 사람이 틀린 문장을 모아 표시하려면 비용이 엄청납니다.
다듬은 **맞게 쓴 문장에서 문제와 정답을 동시에** 만듭니다.

```
원문(위키백과): "그는 의사가 되었다."
   → 슬롯 '되' 발견
   → 문제(특징): "그는 의사가 ▒었다."
   → 정답(라벨): "되"   ← 원문에 쓰인 글자가 곧 정답
```

위키백과 문장은 편집된 글이라 대부분 맞게 쓰였습니다. 그러므로 "쓰인 글자 = 정답"으로 간주합니다.
**틀린 문장 코퍼스가 필요 없다**는 것이 이 방식의 가장 큰 이점입니다.

### `ml/generate_data.py`가 하는 일

1. **수집(`fetch`)**: 위키백과 API로 문서 도입부를 무작위로 가져옵니다(20개씩 400번).
2. **검색 수집(`fetch-search`)**: 특정 표현(`term`)이 든 구절을 위키 검색으로 모아 슬롯이 든 문장을 보충합니다.
3. **정제(`_sentences`)**: 마침표 기준으로 문장을 나누고, **길이 10~200자**, **한글이 40% 이상**인 것만 씁니다(수식·외국어 제거).
4. **보강**:
   - `COLLOQUIAL_SEED`: 위키는 격식체라 `안 돼요.`, `가도 돼?` 같은 구어가 적어서, 손으로 쓴 구어 문장 목록을 더합니다.
   - `_augment_doe`: 문장에 `되어`가 있으면 `돼`로 바꾼 변형을 같은 문장 그룹으로 추가합니다(`되어` = `돼`).
5. **슬롯 수확(`build`)**: 문장마다 `(라벨, 문장 그룹, 특징)`을 TSV 파일로 씁니다.

### "그룹" 번호가 중요한 이유

```python
group = sentence_group(sent)    # 문장의 해시값 = 그 문장에서 나온 모든 슬롯의 공통 번호
```

같은 문장에서 나온 두 슬롯은 주변 12글자가 대부분 겹칩니다. 이 둘이 학습용과 시험용에 갈라져 들어가면, 모델이 "시험 문제를 이미 본 것"과 같아집니다(**누수**).
그래서 그룹 번호를 붙여 **문장 단위로** 나눕니다(7.7).

## 7.4 특징: 글자 조각 세기 (TF-IDF)

기계는 글자를 못 읽고 숫자만 다룹니다. `그렇게 하면 안 ▒요.`를 숫자로 바꾸는 방법이 **글자 n-gram**입니다.

**n-gram**은 연속한 n글자 조각입니다. 2~4글자 조각을 전부 뽑습니다(`ngram_range=(2, 4)`).

```
"안 ▒요." 에서
  2글자: "안 ", " ▒", "▒요", "요."
  3글자: "안 ▒", " ▒요", "▒요."
  4글자: "안 ▒요", " ▒요."
```

`char_ngrams(text, 2, 4)`가 이 일을 합니다. 실제 예문 `그렇게 하면 안 ▒요.`에서는 **30개**의 조각이 나왔고 전부 모델 어휘에 있었습니다.

### TF-IDF: 조각마다 무게 붙이기

- **TF(Term Frequency):** 그 조각이 이 문장에 몇 번 나왔나(개수).
- **IDF(Inverse Document Frequency):** 그 조각이 전체 학습 데이터에서 **얼마나 드문가**. 드물수록 값이 큽니다.

어디에나 있는 조각(`하는`)은 IDF가 작아 영향이 약하고, 드문 조각일수록 IDF가 커서 판단에 더 크게 반영됩니다. (어느 조각이 실제로 큰 힘을 갖는지는 7.5에서 손계산으로 봅니다.)

```
조각 값 = (개수) × IDF
그 다음 전체를 길이 1로 정규화(L2): 값 ÷ √(값들의 제곱합)
```

정규화를 하는 이유는 문장이 길다고 값이 커지지 않게 하려는 것입니다.

## 7.5 로지스틱 회귀: 조각마다 투표하기

학습이 끝나면 모든 조각에 **가중치(w)**라는 숫자가 하나씩 붙습니다. 양수면 한쪽 답으로, 음수면 반대쪽으로 미는 힘입니다.

```
z = Σ (조각 값 × 가중치) + 절편
P(클래스 1) = 1 / (1 + e^(−z))      ← 시그모이드: 어떤 z도 0~1 사이 확률로 바꿔 줌
```

- `z`가 0이면 P=0.5, 크면 1에 가깝고, 작으면 0에 가깝습니다.
- **절편**은 "조각을 하나도 못 봤을 때의 기본 치우침"입니다. doe 모델은 −0.0566입니다.

### 실제 손계산 (doe 모델, 배포된 `.ddm`을 직접 읽음)

`classes_ = ['돼', '되']`이므로 **클래스 1은 `되`**입니다. (순서가 중요합니다. 코드에서 `classes.index(...)`로 항상 찾아 씁니다.)

**예 ①** `그렇게 하면 안 ▒요.`

```
조각 30개 → z = −2.254 → P(되) = 0.0950, P(돼) = 0.9050
되 쪽으로 미는 조각:   ' 하면'(+0.12) '게 '(+0.09) '하면'(+0.08)
돼 쪽으로 미는 조각:   '▒요'(−0.36) ' 안'(−0.27) ' ▒요'(−0.26) '안 '(−0.25)
```

`▒요`(가린 자리 바로 뒤에 `요`)가 가장 강하게 `돼`로 밉니다. "돼요"는 있어도 "되요"는 틀린 표기라는 학습 결과입니다.

**예 ②** `일이 잘 ▒면 좋겠다.`

```
z = +1.868 → P(되) = 0.8662
되 쪽으로 미는 조각:  '▒면'(+0.73) '▒면 '(+0.48) ' ▒면'(+0.35)
```

`▒면`이 가장 강하게 `되`로 밉니다. 이 손계산 결과가 `model.predict_proba()` 출력 `[0.1338, 0.8662]`과 일치했습니다.

> 이것이 모델의 전부입니다. 거대한 "AI"가 아니라 **조각마다 붙은 숫자표 하나**와 합산 한 번입니다.
> 어휘 17만 개(doe 모델 175,671개)와 각각의 가중치·IDF가 모델 파일의 전체 내용입니다.

## 7.6 학습 설정 (`ml/train.py`)

```python
pipe = Pipeline([
    ("tfidf", TfidfVectorizer(analyzer="char", ngram_range=(2, 4),
                              min_df=2, max_features=200_000)),
    ("clf",   LogisticRegression(max_iter=2000, class_weight="balanced")),
])
pipe.fit(X_train, y_train)
```

| 설정 | 뜻 |
|---|---|
| `analyzer="char"` | 단어가 아니라 글자 단위로 조각을 냄 |
| `ngram_range=(2,4)` | 2~4글자 조각 |
| `min_df=2` | 학습 데이터에 **2번 미만** 나온 조각은 버림 (우연한 조각 제거) |
| `max_features=200_000` | 어휘 최대 20만 개 |
| `class_weight="balanced"` | 한쪽 답이 훨씬 많아도 양쪽을 공평하게 학습 (되가 돼보다 많음) |
| `max_iter=2000` | 최대 반복 횟수 |

**빌려 쓴 것:** `TfidfVectorizer`, `LogisticRegression`, `Pipeline`은 scikit-learn(sklearn) 라이브러리입니다. 학습 알고리즘은 빌려 오고, **가중치는 이 저장소에서 처음부터 학습한 것**입니다.

## 7.7 얼마나 믿을까: 시험과 문턱

### 시험용 분리

```python
groups = sorted({g for _, g, _ in rows})
random.Random(SEED).shuffle(groups)                     # SEED = 42
holdout = set(groups[: max(1, int(len(groups) * 0.1))])  # 문장 그룹의 10%
```

**문장 그룹 단위**로 10%를 시험용으로 떼어 놓습니다. 학습에 한 번도 쓰지 않은 문장입니다.

### 문턱(threshold)

모델이 "반대 형태일 확률이 0.8"이라고 해도 곧바로 지적하지 않습니다. **문턱 이상일 때만** 지적합니다.

```
P(반대 형태) ≥ 문턱  →  교정 제안
```

문턱이 낮으면 많이 잡지만 멀쩡한 걸 건드리는 일이 늘고, 높으면 안전하지만 놓칩니다.

### 문턱을 사람이 정하지 않는다

```python
FP_BUDGET = 0.005                # 정문을 잘못 건드리는 비율 0.5% 이하
CANDIDATE_THRESHOLDS = [0.5, 0.6, 0.7, 0.8, 0.9, 0.95, 0.97, 0.99, 0.995]

for t in CANDIDATE_THRESHOLDS:             # 낮은 값부터
    if t <= min_safe: continue              # 등록된 회귀 사례 위반 → 건너뜀
    fp_rate, error_recall = _evaluate_threshold(pipe, X_test, y_test, t)
    if fp_rate <= FP_BUDGET:
        chosen = {...}; break                # 예산을 지키는 가장 낮은 문턱
```

**"오탐률 예산을 지키는 가장 낮은 문턱"**을 측정이 정합니다.

### 모델을 아예 안 싣는 조건

```python
if len(test) >= MIN_TEST and accuracy >= majority_share + MIN_ACCURACY_MARGIN:
```

- 시험 표본이 100개 미만이면 오탐률 추정이 잡음이므로 **거부**.
- 정확도가 "늘 많은 쪽만 찍는 것"보다 **5%p 이상** 높지 않으면 거부(진짜로 구별을 못 배운 것).
- 어떤 문턱에서도 예산을 못 지키면 거부.

거부된 쌍은 `meta.json`에 `accepted: false`로 기록되고 서버는 그 쌍을 아예 로드하지 않습니다. **"믿을 수 없는 층은 싣지 않는다."**

### 회귀 사례(forbidden slots)

`eval/qa/regressions.jsonl`에는 "과거에 틀리게 고쳤던 문장"이 등록되어 있습니다. 시험용 균형 데이터로는 이런 특이 사례가 안 보이므로, **문턱이 그 사례들의 반대 확률보다 높아야** 한다는 조건을 문턱 선택에 직접 넣었습니다.

```python
min_safe = max(min_safe, proba[1 - classes.index(written)])   # 등록된 '건드리면 안 되는' 자리의 반대 확률
...
if t <= min_safe: continue
```

## 7.8 배포 형식 `.ddm`

학습은 sklearn으로 하지만 **서버에는 sklearn을 설치하지 않습니다.** 대신 학습 결과를 자체 형식으로 내보냅니다.

### 왜

| | 피클(`.joblib`) | `.ddm` |
|---|---|---|
| 모델당 메모리 | 약 117MB (어휘 20만 개를 파이썬 문자열 객체로 펼침) | 5.7MB |
| sklearn 버전 | 묶임 (버전이 다르면 읽기 실패 가능) | 안 묶임 (순수 데이터) |
| 필요한 패키지 | sklearn, numpy, joblib | 표준 라이브러리만 |

### 구조 (`app/linear_model.py`)

```
[JSON 한 줄: 메타(클래스, n-gram 범위, 절편 등)]
[offsets: 정수 배열 — 각 조각의 위치]
[idf:     실수 배열]
[coef:    실수 배열]
[terms:   정렬된 모든 조각을 UTF-8 바이트로 이어 붙인 덩어리]
```

조각을 찾을 때는 **이진 탐색**(정렬된 목록에서 가운데를 찍어 앞뒤를 가르는 스무고개)을 씁니다.

```python
def _index(self, token: bytes) -> int:
    lo, hi = 0, len(offsets) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if terms[offsets[mid] : offsets[mid+1]] < token: lo = mid + 1
        else: hi = mid
    ...
```

어휘가 17만 개여도 약 18번이면 찾습니다.

### 변환을 믿을 수 있는 이유

수식을 손으로 옮겨 적었으므로 틀릴 수 있습니다. 그래서 `ml/export_models.py`가 **내보낼 때마다 sklearn 원본과 확률을 대조**하고, 차이가 `1e-12`를 넘으면 **파일을 쓰지 않습니다**. 현재 최대 오차는 `5.55e-16`(컴퓨터의 소수 계산 오차 수준)입니다.

## 7.9 추론: 규칙이 먼저, 모델은 나중에 (`checkers/confusion.py`)

모델 하나를 돌리기 전에 **형태론 게이트**가 먼저 봅니다. 문법으로 정해지는 자리는 확률을 묻지 않고 확정합니다.

```python

if forced is not None:
    if forced != written:

    continue                                  # 모델을 부르지 않음
p_other = ...
if p_other >= threshold:
    issues.append(RawIssue(..., confidence="medium", ...))
```

### 게이트 일람

| 쌍 | 조건 | 확정 | 근거 |
|---|---|---|---|
| 되/돼 | 뒤에 `고 게 기 니 나 냐 네 는 면 며 자 거든 어 었 겠 시`가 옴 | `되` | `돼`는 `되어`의 준말이라 이런 어미가 바로 붙을 수 없음 (`돼겠`, `돼시` 없음) |
| 되/돼 | 뒤에 `서 요 야`가 옴 | `돼` | 줄어든 꼴에만 붙는 어미 |
| 되/돼 | 어절 끝(뒤가 한글 아님) | `돼` | 어간 `되-`는 어미 없이 못 섬 |
| 되/돼 | Kiwi가 `되`를 연결어미(EC)로 읽음 | `되` | `적되, 하되`의 `-되`는 동사 `되다`가 아님 |
| 안/않 | `않`이 어절 끝 | `안` | `않`은 `않다`의 어간, 홀로 못 섬 |
| 안/않 | `-지` 틀 뒤 | `않` | `-지 않다` 틀 |
| 던/든 | 어절 끝 `든/EC` 뒤에 명사 | `던` | `-든`은 연결어미라 명사를 못 꾸밈 |
| 던/든 | `든`을 ETM(관형사형)으로 읽음 | `던` | 관형사형 어미는 `-던`뿐 |
| 던/든 | 이름 속 `든`, 나열 `-든 -든`, 의문사 뒤 | `든`(잠금) | 비외르든·히든카드, `먹든 말든`, `무엇을 하든` |
| 던/든 | `얼마나 ~던지` | `던`(잠금) | 회상 감탄 |
| 로서/로써 | 명사형 어미(ETN) 뒤의 `-으로서` | `로써` | 행위는 자격이 아니라 수단 |

> 이 표의 거의 모든 행이 "확률이 자신 있게 틀리는 부류를 문법으로 잠근 것"입니다. 예를 들어 `쓰든 모자의`를 모델은 `든`이 맞다고 볼 수 있지만, 명사를 꾸미는 자리에는 `-든`이 못 오므로 문법이 `던`을 확정합니다. 실측: 든→던 오류 492건 중 405건(82.3%)을 이 규칙이 잡았고 정문 오탐은 0건.

### 실제로 돌려 본 결과

```
안/않
  '나는 안 먹었다.'          슬롯 안  P(반대 않)=0.002 → 침묵
  '그는 않 갔다.'            슬롯 않  P(반대 안)=0.998 → 형태론 확정→안
되/돼
  '시간이 되도록 일찍 와.'    슬롯 되  P(반대 돼)=0.192 → 침묵
  '그러면 안 되도 괜찮다.'    슬롯 되  P(반대 돼)=0.798, 문턱 0.6 → 모델: 제안 돼
  '이렇게 해도 되?'          슬롯 되  → 형태론 확정→돼 (어절 끝)
던/든
  '먹든 말든 상관없다.'      슬롯 든  → 형태론 확정→든 (나열 잠금)
  '어릴 때 살든 집이 그립다.' 슬롯 든  → 형태론 확정→던 (관형 수식)
로서/로써
  '칼로서 빵을 잘랐다.'       슬롯 로서 P(반대 로써)=0.517 문턱 0.7 → 침묵(점선 후보)
```

`그러면 안 되도 괜찮다`처럼 **게이트가 못 정하는 자리**(`도`가 `돼도`와 `되도록` 둘 다 가능)에서만 모델이 발언합니다.

## 7.10 여섯 모델의 성적표 (`meta.json` 실제 값)

| 모델 | 학습 행 | 시험 행 | 정확도 | 최다 클래스 비율 | 문턱 | 정문 오탐 | 오류 재현율 | 실행 |
|---|---|---|---|---|---|---|---|---|
| an(안/않) | 260,639 | 28,959 | 99.86% | 50.3% | 0.5 | 0.14% | 99.9% | ✅ |
| doe(되/돼) | 35,258 | 3,917 | 99.54% | 81.4% | 0.6 | 0.15% | 99.2% | ✅ |
| den(던/든) | 13,239 | 1,470 | 98.64% | 78.2% | 0.7 | 0.41% | 94.1% | ✅ |
| roseo(로서/로써) | 60,464 | 6,718 | 87.96% | 50.2% | 0.7 | 0.15% | **20.3%** | ✅ |
| reo(러/려) | 279,787 | 31,087 | 98.65% | 50.0% | 0.8 | 0.26% | 93.7% | ⏸ 꺼 둠 |

### "정확도"와 "최다 클래스 비율"

doe는 정확도 99.54%이지만 `되`가 81.4%라서 "늘 `되`"만 찍어도 81.4%가 나옵니다. 진짜 실력은 그 위의 18%p입니다.
roseo는 87.96%인데 최다 비율이 50.2%라 38%p 위에 있어 학습은 됐지만, **문턱 0.7에서의 오류 재현율은 20.3%**에 그칩니다.
이 값은 "모델 혼자 잡는 비율"이고, 실제 엔진의 로서/로써 재현율은 규칙 게이트 덕분에 더 높습니다(평가 0.85, 11장).

### reo, dae는 왜 꺼 놓았나

학습 게이트는 넉넉히 통과했습니다. 그러나 **평가할 오류 표본이 거의 없습니다**(구어 오류 1,073행에서 reo 0건, dae 2건).
평가 근거 없이 도는 층은 235MB를 먹으면서 오탐 위험만 지는 "부채"라고 판단해 `_SILENCED_FORMAL = {"dae", "reo"}`로 로드 자체를 건너뜁니다(`DADEUM_PAIRS=dae,reo`로 되살림).

## 7.11 이 방식의 한계

1. **글자 조각만 봅니다.** 의미를 모릅니다. `칼로서`/`칼로써`는 수단/자격이라는 **의미**의 차이인데 글자 창으로는 잘 안 보입니다(roseo 정확도 88%).
2. **문맥 창이 12글자뿐입니다.** 앞뒤가 멀면 못 봅니다.
3. **학습 데이터가 위키(격식)라서** 구어 표현에 약합니다. 그래서 구어 시드 문장을 손으로 보탰습니다.
4. **어디가 슬롯인지는 사람이 정합니다.** 슬롯 정규식에 안 걸리면 모델은 존재를 모릅니다.
