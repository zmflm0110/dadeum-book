# 10장. 띄어쓰기: 가장 큰 검사 영역

띄어쓰기는 한국어 맞춤법에서 **오류가 가장 많고 동시에 허용이 가장 많은** 영역입니다.
"맞는 걸 틀렸다고 하는" 위험이 가장 큰 곳이라서 다듬 코드의 띄어쓰기 부분은 가장 조심스럽고 가장 큽니다
(`spacing.py` 758줄 + `spacing_extra.py` 922줄 + `spacing_tiers.py` 103줄).

이 장의 실행 결과는 제가 `check_spacing`을 직접 불러 얻은 값입니다.

## 10.1 문제의 모양

띄어쓰기 오류는 두 방향입니다.

| 방향 | 예 | 처리 |
|---|---|---|
| **붙여 써야 하는데 띄어 씀** (삭제) | `안녕 하세요` → `안녕하세요` | 공백을 지움 |
| **띄어 써야 하는데 붙여 씀** (삽입) | `너무많아서` → `너무 많아서` | 공백을 넣음 |

그리고 **둘 다 맞는 자리**가 많습니다(맞춤법 제47·48·49항: 보조용언, 전문 용어, 고유명사).
이것이 가장 어려운 점입니다. 모델이 "이쪽이 더 흔하다"고 해서 고쳐 버리면 **맞는 글을 틀렸다고 하는** 도구가 됩니다.

## 10.2 3단계 판정: 필수 / 권장 / 허용 (`spacing_tiers.py`)

설계 원칙이 이 파일 맨 위에 있습니다.

| 단계 | 뜻 | 동작 | 신뢰도 |
|---|---|---|---|
| **필수** | 확정 오류 | 자동 교정 | high |
| **권장** | 근거는 있으나 확정 못 함 | 제안만 | low (점선) |
| **허용** | 규범이 둘 다 허용하거나 근거가 약함 | **침묵** | — |

> "허용 범위를 넓게 잡는다." 애매하면 전부 '허용'으로 보낸다. 침묵이 기본값이다.

```python
ADVISE_MIN = 0.90            # 모델 확률이 이 위여야 '권장'으로라도 올라간다
MODEL_NEVER_AUTOFIXES = True # 모델 단독으로는 자동 교정 권한을 주지 않는다
```

**"필수는 모델이 정하지 않는다."** 자동 교정(high)은 오직 **규칙이 정한 자리**에서만 나옵니다. 모델(태거)의 말은 아무리 확신해도 low(점선)까지만 올라갑니다.

## 10.3 전체 구조: 네 갈래가 한 목록으로

`check_spacing(text, kiwi)`가 네 가지 길을 모아서 정리합니다.

```
                  ┌─ ① 삽입  _insertions   BiGRU 태거 (확률 ≥ 0.90, 한글-한글 경계)   → low
check_spacing ────┼─ ② 삭제  _deletions    kiwi.space() 가 지운 공백                   → medium
                  ├─ ③ 규칙(spacing.py)    정도부사·부정부사·보조용언·시간명사·수+단위·명사+있다/없다·관형사+명사·부사+용언·조사·접미사
                  └─ ④ 규칙(spacing_extra) 문장부호·합성어·접두사·서술격조사·어미·연어·경계 판별·명사형·합성용언 … 20여 종   → high
```

### 합치는 법 (코드 끝부분)

```python
taken = set()
uniq = []
for h in rule_hits:                       # 규칙 결과 중 같은 자리는 하나만
    if (h.start, h.end) in taken: continue
    taken.add((h.start, h.end)); uniq.append(h)
return uniq + [i for i in out if (i.start, i.end) not in taken]    # 태거·삭제는 규칙이 안 차지한 자리만
```

**규칙이 확정한 자리는 태거의 저신뢰 제안보다 우선합니다.** 같은 자리에 두 개가 뜨면 중복 밑줄로 보이기 때문입니다.

## 10.4 ① 삽입: BiGRU 태거

### BiGRU가 무엇인가

**GRU**는 글을 앞에서 뒤로 읽으며 "지금까지 본 내용"을 기억에 쌓아 가는 작은 신경망입니다. **Bi**는 양방향이라는 뜻으로, 앞→뒤와 뒤→앞을 둘 다 읽어 합칩니다.

```
입력:  하 는 영 화 재 밌 었 다        (공백을 전부 지운 글자열)
출력:  0.1 0.97 0.1 0.8 0.1 0.1 0.1 0     ← 각 글자 "뒤에 공백이 올 확률"
```

구조(`ml/spacing_model_nn.py`):

```python
class SpacingTagger(nn.Module):
    def __init__(self, vocab, emb=64, hidden=192, layers=2, dropout=0.2):
        self.emb = nn.Embedding(vocab, emb)                     # 글자 → 64개 숫자
        self.rnn = nn.GRU(emb, hidden, num_layers=2, bidirectional=True)
        self.out = nn.Linear(hidden * 2, 1)                     # 글자마다 점수 1개
    def forward(self, x):
        h, _ = self.rnn(self.emb(x))
        return self.out(self.drop(h)).squeeze(-1)
```

**왜 BiGRU인가** (코드 설명): 띄어쓰기 판단은 **양방향 국소 문맥**이 거의 전부입니다. `할수`를 띄울지는 앞의 관형형과 뒤의 `있다`를 같이 보면 정해집니다. 장거리 의존은 거의 필요 없어서 작은 모델로도 충분하다고 보았습니다. 사전학습 모델(RoBERTa 등)을 미세조정하는 방식과 정면으로 비교하기 위해 만든 것입니다.

### 추론할 때: 공백을 일부러 전부 지운다

```python
stripped_chars = [ch for ch in text if not ch.isspace()]
probs = tagger.predict_proba("".join(stripped_chars))
```

**학습할 때 "공백을 지운 문장 전체"를 입력으로 했으므로 추론에서도 똑같이 넣습니다.** 어절을 하나씩 따로 넣으면 문맥이 사라져 판정이 나빠집니다.
그런 다음 원문의 **어절 내부 경계만** 봅니다. 이미 공백이 있는 자리는 건드리지 않습니다(삭제는 ②의 일).

### 통과해야 하는 문들

```python
if probs[k] < ADVISE_MIN: continue            # 0.90 미만이면 침묵
if i1 != orig_index[k + 1]: continue          # 원문에 이미 공백이 있음
if not (_is_hangul(text[i1-1]) and _is_hangul(text[i1])): continue   # 한글-한글 경계만
if i1 in aux_starts: continue                 # 47항 허용형이면 침묵
if i1 in inside_morph: continue               # 형태소 안쪽이면 불가능
```

| 문 | 이유 |
|---|---|
| 한글-한글만 | 숫자·영문·부호 옆 분리(`17일 ~ )`)가 정문 오탐의 최대 부류였음 |
| 형태소 안쪽 제외 | 태거는 위키(격식)로 학습해서 구어 어미를 모름. `도와드릴게요`의 `ᆯ게요`를 `…ᆯ게 \| 요`로 쪼개려 한 적이 있음 |
| `aux_starts` | 보조용언이 `-아/-어`나 관형사형 뒤에 있으면 붙여 써도 맞음 |

### 태거의 한계 (코드 설명에 명시)

> 태거를 "처음부터 다시 띄우는" 과제로 재면 **문장 완전일치가 44.8%**라서, 절반 이상의 문장에서 최소 한 군데를 틀린다. 그대로 자동 교정에 쓰면 안 된다.

F1 점수 0.945는 "경계 하나하나"의 점수이고, **문장 전체를 다 맞히는 비율은 44.8%**입니다. 그래서 low(점선) 이상은 못 올라갑니다.

### 공백 이동 문제

원문 `검토 해보다`가 `검토해 보다`로 바뀌는 경우 diff는 "한 글자 삽입 + 한 글자 삭제"로 나옵니다. **공백만 지운 순수 삭제만 받는** 조건이라 이런 "공백 이동"은 절반이 음절이라 걸러집니다. 이 한 줄 조건이 코드 주석에서 "위험을 녹여 없앤다"고 표현됩니다.

## 10.6 ③ 규칙 (`spacing.py`)

여기서부터 모두 **high**입니다. 각 규칙은 "위키 정문 10,000문장에 먼저 걸어 보고 형태를 좁혔다"는 방식으로 만들어졌습니다.

| 규칙 | 근거 조항 | 예 | 핵심 조건 |
|---|---|---|---|
| `_degree_adverb_rule` | 제2항 | `너무많아서` → `너무 많아서` | 정도부사 목록(너무·매우·아주·몹시·굉장히·무척·상당히·꽤·되게·하도·약간·훨씬·더욱)만 |
| `_aux_verb_rule` | 제47항 | `하고있다` → `하고 있다` | `-지/-게/-고/-어야` 뒤의 보조용언만(-아/-어 뒤는 허용이라 제외) |
| `_negation_rule` | 제2항 | `안되요` → `안 되요` | `안·못` + 용언. 굳은 말(`못하다`, `안되다`) 제외 |
| `_time_noun_rule` | 제42항 | `갈때` → `갈 때` | 앞말 종류마다 따로 좁힘 |
| `_numeral_unit_rule` | 제43항 | `세번째` → `세 번째` | 수 관형사 + 단위 명사 |
| `_noun_exist_rule` | 제2항 | `재미 없다` ↔ 붙임 | 명사 + 있다/없다/같다 |
| `_determiner_noun_rule` | 제2항 | `이런영화` → `이런 영화` | 관형사 + 명사 |
| `_adverb_verb_rule` | 제2항 | 부사 + 용언 | 굳은 부사 제외 |
| `_josa_space_rule` | 제41항 | `친구 와` → `친구와` | 조사는 앞말에 붙임 |
| `_suffix_space_rule` | — | `안녕 하세요` → `안녕하세요` | 파생 접미사 -하다·-되다·-시키다 |

### 규칙마다 이어진 "빼기" 목록의 실제 예

**`_negation_rule`** (안/못 + 용언):

| 빼는 것 | 이유 (코드 주석의 실측) |
|---|---|
| `못하다`, `못되다`, `안되다` | 위키 `못하다` 13건이 전부 정문. `못되다`(성품)·`안되다`(가엾다)는 뜻으로만 갈려 글자로 못 가름 |
| 앞말에 붙은 `안`/`못` | `편안`, `잘못`의 일부일 수 있음. 조사 뒤(`B급도안`)만 받음 |
| 《》·〈〉·『』·「」 안 | 작품 제목은 만든 이가 쓴 그대로가 이름. `《짱구는 못말려》`가 오탐이었음 |

**`_time_noun_rule`** (때/동안/전/후/중/이상/이하 …): 앞말 종류에 따라 규칙이 7갈래입니다. 코드 주석:

| 앞말 | 허용 | 근거 |
|---|---|---|
| 관형형 | 때·동안·내내·무렵·즈음 | `끝날 때` |
| 명사 | `때문` | 의존명사 |
| 수량 | 이상·이하 | 명사 뒤는 `정신이상` 합성어 |
| 명사형(-기)·시간 단위 | 전·후 | **명사 뒤 `전·후`는 위키 9+9건이 거의 전부 오탐**: 격투전(戰)·개막전·기원전·얼후(악기)·곽상훈(이름) |
| 두 음절 이상 일반명사 | 때·중 | 위키 `중` 39건 중 오탐 11건(`혈중`, `작중`, `초중`, `윤희중`)을 이 조건이 걸러 냄 |

시도하고 버린 것도 기록돼 있습니다: `영상속에`, `환경속에도` 같은 `속`. 생물 분류 `속(屬)`(마타리속, 스콜로플락스속)은 붙여 쓰는데, 앞뒤 어디에도 둘을 구별할 신호가 없고 "그 단어를 아는지"만이 구별합니다.

### 허용 형태: "지켜야한다"의 숨은 불일치

실행해 보았습니다.

```
'도와드리다'   → (없음)                                  ← 본용언 + -아/-어 + 보조용언: 허용
'지켜야한다'   → [aux_verb_rule|high] '한' → ' 한'         ← 규칙은 띄우라고 함
```

`_aux_verb_rule`의 설명대로 `-어야` 뒤는 47항의 붙여 쓰기 허용 목록(`-아/-어`)에 없습니다. 그런데 같은 파일의 `_delete_protected` 설명문은 `지켜야 한다 ↔ 지켜야한다`를 "둘 다 맞는 예"로 들고 있습니다. **코드 주석 두 곳이 서로 어긋납니다.** 동작은 앞의 규칙(띄우라)입니다. 규범상 보조사 `야`가 낀 `-어야`는 허용이 아니라는 쪽이 맞지만, 이 불일치는 문서 정리 후보입니다.

## 10.7 ④ 추가 규칙 (`spacing_extra.py`)

2026-09-14 탐침에서 **로컬 엔진이 아무 표시도 못 한** 부류들을 메우려고 만든 파일입니다.

### 만들어진 이유

> Kiwi는 대부분의 정답 띄어쓰기를 이미 알고 있었다(`kiwi.space`). 그런데 `spacing.py`가 **삭제만** 쓰고 삽입은 태거 0.90 문턱에 맡겨 버려지고 있었다.
> "Kiwi 삽입 ∧ 태거"를 그대로 켜면 위키 정문에서 p≥0.9로도 **395건**이 발동했다(대부분 허용 합성어 `총괄 프로듀서`). 쓸 수 없었다. 그래서 **부류별 규칙**이다.

즉 Kiwi의 제안을 통째로 믿을 수 없어서 **"어떤 부류인지 명시한 뒤에만"** 믿습니다.

### 규칙 목록 (`_RULES`)

| 이름 | 하는 일 | 예 (실행 결과) |
|---|---|---|
| punct_space | 문장부호 뒤 다음 문장이 붙음 | `재밌다.다음에` → `다. 다음에` |
| punct_cling | 부호 앞의 공백 | `많다 .` → `많다.` |
| compound_predicate | 명사 + 용언 합성(재미없다 등) | `재미 없다` → `재미없다` |
| question_mark | 의문형 어미 뒤 마침표 | (6장) |
| compound_time | 지난주·그동안·매년 / 이번 주·다음 달 | |
| prefix_space | `제-`는 숫자에 붙임 | |
| numeral_spacing | 수 + 단위 (일 년, 열 시) | |
| copula_space | 서술격 조사 `이다`는 앞말에 붙임 | |
| ending_space | `-ㄹ수록`, `-는지` | |
| pronoun_josa | 대명사 뒤 `마저·뿐` | |
| noun_verb | 명사 + 용언 연어(짜증 나다) | |

### `runon_boundary`의 사연 (경계 모델 이전의 방식)

붙여 쓴 어절의 **조사·어미 바로 뒤**를 띄우는 규칙입니다. 이 규칙은 8장의 경계 모델이 나오기 **전**의 방식이고, 지금도 보조로 돕니다.

**조건이 많은 이유**는 오탐 사례가 그대로 조건이 되었기 때문입니다.

| 조건 | 막는 실제 오탐 |
|---|---|
| 한 음절 앞말은 **단어 첫머리일 때만** 믿는다 | `면역글로\|불린`, `피앙케\|토하는` (외래어 조각) |
| 관형형 + 명사: 동사·보조용언 뒤나 두 음절 이상 형용사 뒤만 | `짠맛`, `큰키나무`, `흰얼굴`, `같은해` (합성어) |
| 어절 첫머리 관형형 + 한 음절 명사 제외 | `마른내로` (도로명) |
| 어미 뒤 `서` 제외 | `옮기므로\|서` (`서다`를 잘못 읽음) |
| 굳은 부사(`_LEXICAL_ADVERBS`: 잘·못·안·늘·함께·같이·가득…) 제외 | 합성어를 만드는 부사 |

한계도 명시돼 있습니다. 8장의 서문대로 이 규칙은 **실사용 오류 36개 경계 놓침 중 4개만** 회복했습니다.

## 10.8 실행 결과 정리 (제가 직접 돌림)

| 입력 | 결과 | 출처 |
|---|---|---|
| 너무많아서 놀랐다 | `많` → ` 많` | degree_adverb_rule (high) |
| 그렇게 하면 안되요 | `안` → `안 ` | negation_context_rule (high) |
| 하고있다 | `있` → ` 있` | aux_verb_rule (high) |
| 도와드리다 | (없음) | 47항 허용 |
| 안녕 하세요 | 공백 삭제 | suffix_space_rule (high) |
| 세번째 갔다 | `번` → ` 번` | numeral_unit_rule (high) |
| 재밌다.다음에 보자 | `다` → ` 다` | punct_space_rule (high) |
| 친구 와 갔다 | 공백 삭제 | josa_space_rule (high) |
| 하는영화를 봤다 | `영` → ` 영` | etm_noun_rule (high) |
| 알아 내다 | 공백 삭제 | compound_verb_rule (high) |
| 이 영화 재미 없다 | `재미 없다`→`재미없다` | compound_space_rule (high) |
| 핡교가는길에 갔다 | `길` → ` 길` | tagger_space (low) |
| 지난주에 갔다 / 영화 보다 / 짜증 난다 / 점심때 먹었다 / 총괄 프로듀서 | (없음) | 정문 |

`총괄 프로듀서`, `점심때`가 **조용한 것**이 설계의 성공입니다. 둘 다 위키에서 태거가 틀리게 띄우고 싶어 하던 허용 합성어입니다.

## 10.9 이 장에서 가져갈 것

1. 띄어쓰기는 **허용이 많은 영역**이라 "필수 / 권장 / 허용" 3단계로 나누고 **침묵이 기본값**이다.
2. 자동 교정(high)은 **규칙이 정한 자리**에서만. 모델은 점선까지만.
3. 규칙 하나하나가 **위키 정문에서 발동한 것을 전수로 읽고 좁힌 결과**다. 조건이 많은 것은 오탐 사례의 흔적이다.
4. 같은 코드가 두 곳에서 어긋날 수 있다(`지켜야한다` 설명 불일치). 문서도 코드와 같이 검증해야 한다.
5. 층이 환경에 따라 켜지고 꺼진다. 결과가 다르면 `/api/health`부터 본다.
